# StockResearch PRD

## 1. 产品定义

StockResearch 是一个在个人电脑上运行、联网获取公开市场数据、由用户自行配置模型的 AI 投顾与 AI 投研 MVP。

它的目的不是成为可商业化的股票终端，也不是替用户交易，而是通过一个完整、可信、易演示的产品，展示作者对以下问题的理解：

- AI 如何帮助普通投资者理解持仓、风险和市场变化；
- AI 如何帮助金融专业人士组织多源信息、形成研究过程；
- 同一套事实数据如何用不同的信息密度服务两类用户；
- AI 产品如何把对话、主动发现、工具调用和可验证过程组合成新的交互范式。

## 2. 目标用户

### 2.1 个人投顾用户

有少量 A 股持仓，但不熟悉专业术语，希望快速知道：

- 今天与我的持仓有关的事情是什么；
- 这些变化意味着什么；
- 我的组合暴露了哪些风险；
- 如果要继续了解，下一步应该查看什么信息。

### 2.2 专业投研用户

具备金融基础，希望快速获得：

- 个股、行业和市场的多维研究；
- 数据来源、分析维度和推理过程；
- 多空分歧、置信度与风险因素；
- 可继续追问、对比和验证的研究上下文。

## 3. 成功定义

本项目成功的标准不是功能数量，而是用户首次打开后能在 3 分钟内完成一次有价值的 AI 体验。

量化标准：

- 首次访问无需阅读文档即可完成模式选择并看到示例结果；
- 首页 10 秒内能看懂“今天最值得关注的 1–5 件事”；
- 常用能力最多一次点击可达，全部能力最多两次点击可达；
- 普通用户首屏不出现超过 5 个主要信息块；
- 专业用户可展开完整数据、维度和来源，但默认不挤压普通用户体验；
- 同一问题的普通响应和流式响应在结论、合规处理和卡片数据上保持一致；
- Mock 模式下核心演示不依赖外部 API；
- 正常运行默认连接真实行情、新闻和模型服务，Mock 只用于演示与降级；
- 后端测试、前端测试和生产构建持续通过。

## 4. 产品原则

### 4.1 AI 原生，而不是终端加聊天框

AI 是产品主入口和组织者：

- 用户可以直接描述目标，不必先找到指标页面；
- 系统主动把持仓、行情、新闻和风险连接起来；
- 复杂任务展示 Agent 正在做什么，但不暴露无意义的思维链；
- 结果不是一堵文字，而是“结论 + 依据 + 可继续动作”；
- 用户可以围绕已有报告继续追问，不必重新配置筛选器。

### 4.2 渐进披露

个人投顾和专业投研共享数据与分析能力，只改变默认信息密度和表达方式。

- 个人投顾：先说人话结论、金额影响和关联原因，专业指标折叠；
- 专业投研：先给结构化指标、多维评分、来源和分歧；
- 两种模式都允许展开另一层内容，不复制两套产品。

### 4.3 少而完整

每个模块必须服务一个高频问题。不能明确提升核心体验的功能不进入 MVP。

### 4.4 事实与推理分离

- 行情、持仓、财务数据、新闻属于事实层；
- 评分、解释、辩论和综合属于推理层；
- 数据缺失时必须显式降级，不能由模型补造；
- 结论必须能回到来源或规则。

### 4.5 本地可信

- 单用户、SQLite、localhost；
- 用户自行配置模型与可选数据源；
- 不建立账号系统；
- 不上传持仓到项目自有服务；
- 明确区分浏览器临时配置与本机 `.env` 持久化。

## 5. 核心体验

### 5.1 首页：今日关注

默认首页不是市场仪表盘，而是 AI 生成的个人变化摘要：

1. 与持仓直接相关的价格、新闻或风险变化；
2. 为什么与用户相关；
3. 关键依据和数据时间；
4. “查看详情”或“继续问 AI”。

个人投顾最多 5 条，专业投研最多 12 条。没有重要变化时明确显示“今日无明显变化”，不填充噪声。

### 5.2 AI 对话

一个输入框覆盖：

- 问市场；
- 问个股；
- 问持仓；
- 做风控；
- 做对比；
- 解释术语和报告。

系统自动选择直接回答、工具调用、多维研究或计划执行。高级用户可调整执行方式，但不要求普通用户理解 Agent 类型。

### 5.3 研究结果

统一结果结构：

1. 一句话结论；
2. 关键依据；
3. 风险与不确定性；
4. 数据来源和时间；
5. 可选的完整四维研究与多空分歧；
6. 推荐继续追问的问题。

### 5.4 持仓与风险

持仓页只保留：

- 成本、数量、当前价格和盈亏；
- 行业集中度；
- 一键询问 AI。

风险页只保留：

- 人话风险结论；
- 金额化影响；
- 主要风险来源；
- 可展开的 VaR、回撤、Sharpe 等专业指标。

### 5.5 新闻

新闻不是通用资讯流，只展示：

- 与持仓相关；
- 与关注行业相关；
- 少量市场级重要事件。

每条新闻支持 AI 解释“为什么相关、可能影响路径、哪些事实仍不确定”。

### 5.6 设置

设置按任务分组：

- AI 模型；
- 数据源；
- 显示模式；
- 分析偏好；
- 本地数据。

隐藏低频技术项，提供合理默认值。

## 6. 信息架构

### 6.1 单画布与顶部视角栏

产品只保留一个主画布，不使用左侧栏，也不把功能拆成多个彼此割裂的传统页面。

大盘指数常驻最顶部。其下方固定一行视角与工具按钮：

`[持仓] [风控] [市场] [新闻·研报]    [Copilot]`

- **持仓**是默认视角，回答“我的资产今天怎么样”；
- **风控**回答“我的组合可能怎么亏、风险来自哪里”；
- **市场**回答“今天大盘和市场结构处于什么状态”；
- **新闻·研报**同时容纳研究输入与 AI 研究产出；
- **Copilot**控制全局 AI 面板的展开和收起。

四个主按钮只切换同一画布的内容与当前页面上下文，不创建四套应用外壳。模式切换、数据状态和设置继续放在全局顶栏。

### 6.2 全局 Copilot

Copilot 在所有画布视角都存在：

- 默认折叠为右侧窄条或按钮，不挤压主页面；
- 展开后占据右侧 380–440px，左侧业务页面仍然保留；
- 小屏时可覆盖画布，不要求移动端专门适配；
- 深度任务可以从 Copilot 转入完整研究工作区。

各页面不重复实现完整聊天框，只提供轻量 AI 动作，例如：

- 持仓：“解释今天的盈亏”或“分析这只股票”；
- 风控：“谁对组合风险贡献最大？”
- 市场：“今天市场为什么这样走？”
- 新闻·研报：“解释这条新闻”或“继续追问这份研报”。

点击动作后统一打开全局 Copilot，并显式附加页面上下文。

### 6.3 三层上下文

Copilot 只共享应该共享的内容：

1. **长期用户上下文，全局共享**
   - 持仓；
   - 风险偏好和现金流；
   - 个人投顾 / 专业投研模式；
   - 语言、分析偏好和用户明确保存的记忆。

2. **线程上下文，仅在线程内共享**
   - 当前问题和连续追问；
   - 当前研究对象；
   - 已生成的报告和用户确认的信息。

3. **页面上下文，临时且显式附加**
   - 当前选中的股票、新闻、组合或研究报告；
   - 页面切换不会自动永久写入线程；
   - 用户可一键移除；
   - 默认影响下一次提问，发送后可选择继续保留。

Copilot 顶部必须显示：

- 当前线程；
- 长期上下文摘要；
- 页面上下文标签及移除按钮。

### 6.4 视角切换规则

- 视角切换保留当前线程；
- 视角切换不自动改变“它”“这只股票”等代词指向；
- 新视角有可用上下文时，显示“附加当前画布”操作；
- 用户从画布内 AI 动作进入时，自动附加该对象上下文；
- 深度研究创建独立线程，完成后可保留为历史报告；
- 新对话清空线程内容，但不清空长期用户上下文。

## 7. Agent 契约

### 输入

- 用户问题；
- 当前模式；
- 持仓上下文；
- 用户明确选择的股票；
- 数据源与模型配置；
- 可选的执行偏好。

### 输出

- `reply`：适合当前模式的结论；
- `cards`：结构化事实和研究结果；
- `intent`：实际执行的任务类型；
- `partial`：是否发生降级；
- `sources/status`：数据来源与状态；
- `llm_usage`：本次模型用量。

### 失败与降级

- 股票歧义：展示候选，不猜；
- 单个数据源失败：使用备用源并标注；
- 单个 Agent 超时：返回已完成维度并标记 partial；
- LLM 未配置：引导进入设置或使用 Mock；
- SSE 中断：保留最近 checkpoint；
- 数据不足：返回“无法判断”和缺失项，不生成伪结论。

## 8. 技术架构要求

- FastAPI 路由只负责协议、依赖和序列化；
- 同步与 SSE 使用同一任务路由、领域执行和最终输出处理；
- SSE 只增加进度事件，不复制业务决策；
- 中立性过滤、术语标记、免责声明处理必须有唯一入口；
- 数据 Provider 返回来源、时间和降级状态；
- 前端 API 按领域拆分，页面状态不集中在单一巨型组件；
- Copilot 状态独立于具体页面，页面只通过显式契约提供临时上下文；
- 页面上下文必须可见、可移除，不能暗中污染线程；
- 卡片使用判别联合类型，不用大范围 `try/catch + type assertion`；
- SQLite schema 变更采用可追踪迁移；
- CI 至少覆盖测试、构建和不会新增的静态检查基线。
- 真实 Provider 通过显式 live integration test 验证，默认单测不因第三方超时随机失败。

## 9. MVP 范围

必须保留：

- 双模式与首次引导；
- 今日关注；
- AI 对话与流式过程；
- 个股、行业、市场研究；
- 四维研究与可选辩论；
- 持仓、新闻、风险；
- 示例数据与 Mock；
- 本地 LLM 和数据源配置；
- 数据降级提示；
- 中英文界面。

需要重构：

- 同步/SSE 双轨编排；
- 输出后处理不一致；
- 前端根组件、API 和卡片渲染过度集中；
- AI 对话只存在于单一页面，其他页面仍接近传统信息页面；
- 数据库迁移；
- PRD、README 和真实实现状态不一致；
- 静态检查未形成有效门禁。

## 10. 非目标

- 不上线为公网 SaaS；
- 不做注册、登录、多用户、权限和计费；
- 不做交易下单、自动调仓或券商连接；
- 不做全市场扫描器和传统终端式功能矩阵；
- 不做 Level-2、盘口、复杂技术指标库；
- 不做社区、跟单、排行榜；
- 不做移动端优先和 PWA；
- 不做复杂动画、3D 图表、游戏化；
- 不做独立时间流、收件箱或任务管理视图；
- 不为展示 Agent 数量而增加 Agent；
- 不追求覆盖所有数据源和所有市场。

## 11. 验收标准

- `.prd/PRD.md` 与 `docs/PRD.md` 产品边界一致；
- 普通和流式聊天共享最终输出处理，并且只产生一个最终 `done`；
- 两条聊天路径都有一致性测试；
- 核心功能测试全部通过；
- 前端生产构建通过；
- CI 明确运行后端测试、前端测试和构建；
- README 不再把项目描述为终端或未来 SaaS；
- 四个主视角均可打开同一个 Copilot；
- 视角切换保留线程但不会隐式替换页面上下文；
- 页面上下文在 Copilot 顶部可见且可移除；
- 大盘指数和五个顶部按钮在四个主视角中保持位置不变；
- 未新增任何非目标功能。
