# StockResearch PRD

## 1. 产品定义

StockResearch 是一个在个人电脑上运行、联网获取公开市场数据、由用户自行配置模型的 AI 投顾与 AI 投研 MVP。

它的目的不是成为可商业化的股票终端，也不是替用户交易，而是通过一个完整、可信、易演示的产品，展示作者对以下问题的理解：

- AI 如何帮助普通投资者理解持仓、风险和市场变化；
- AI 如何帮助金融专业人士组织多源信息、形成研究过程；
- 同一套事实数据如何用不同的信息密度服务两类用户；
- AI 产品如何把对话、主动发现、工具调用和可验证过程组合成新的交互范式。

## 2. 目标用户

### 2.1 个人投顾用户

有少量 A 股持仓，但不熟悉专业术语，希望快速知道：

- 今天与我的持仓有关的事情是什么；
- 这些变化意味着什么；
- 我的组合暴露了哪些风险；
- 如果要继续了解，下一步应该查看什么信息。

### 2.2 专业投研用户

具备金融基础，希望快速获得：

- 个股、行业和市场的多维研究；
- 数据来源、分析维度和推理过程；
- 多空分歧、置信度与风险因素；
- 可继续追问、对比和验证的研究上下文。

## 3. 成功定义

本项目成功的标准不是功能数量，而是用户首次打开后能在 3 分钟内完成一次有价值的 AI 体验。

量化标准：

- 首次访问无需阅读文档即可完成模式选择并看到示例结果；
- 首页 10 秒内能看懂“今天最值得关注的 1–5 件事”；
- 常用能力最多一次点击可达，全部能力最多两次点击可达；
- 普通用户首屏不出现超过 5 个主要信息块；
- 专业用户可展开完整数据、维度和来源，但默认不挤压普通用户体验；
- 同一问题的普通响应和流式响应在结论、合规处理和卡片数据上保持一致；
- Mock 模式下核心演示不依赖外部 API；
- 正常运行默认连接真实行情、新闻和模型服务，Mock 只用于演示与降级；
- 后端测试、前端测试和生产构建持续通过。

## 4. 产品原则

### 4.1 AI 原生，而不是终端加聊天框

AI 是产品主入口和组织者：

- 用户可以直接描述目标，不必先找到指标页面；
- 系统主动把持仓、行情、新闻和风险连接起来；
- 复杂任务展示 Agent 正在做什么，但不暴露无意义的思维链；
- 结果不是一堵文字，而是“结论 + 依据 + 可继续动作”；
- 用户可以围绕已有报告继续追问，不必重新配置筛选器。

### 4.2 渐进披露

个人投顾和专业投研共享数据与分析能力，只改变默认信息密度和表达方式。

- 个人投顾：先说人话结论、金额影响和关联原因，专业指标折叠；
- 专业投研：先给结构化指标、多维评分、来源和分歧；
- 两种模式都允许展开另一层内容，不复制两套产品。

### 4.3 少而完整

每个模块必须服务一个高频问题。不能明确提升核心体验的功能不进入 MVP。

### 4.4 极简界面，复杂能力可调出

默认界面保持极简，只显示当前任务最需要的结论、影响和下一步动作。复杂能力必须可调出，但不能常驻挤压首屏。

- 普通用户默认看到摘要、人话解释和关键证据；
- 专业用户可展开数据表、因子详情、来源、模型执行过程和历史研究；
- 高级执行选项进入“更多 / 专业展开 / 数据源详情 / 研究设置”；
- 复杂功能必须从当前任务调出，不以传统终端菜单矩阵呈现。

### 4.5 事实与推理分离

- 行情、持仓、财务数据、新闻属于事实层；
- 评分、解释、辩论和综合属于推理层；
- 数据缺失时必须显式降级，不能由模型补造；
- 结论必须能回到来源或规则。

### 4.6 本地可信

- 单用户、SQLite、localhost；
- 用户自行配置模型与可选数据源；
- 不建立账号系统；
- 不上传持仓到项目自有服务；
- 明确区分浏览器临时配置与本机 `.env` 持久化。

## 5. 核心体验

### 5.1 首页：今日关注

默认首页不是市场仪表盘，而是 AI 生成的个人变化摘要：

1. 与持仓直接相关的价格、新闻或风险变化；
2. 为什么与用户相关；
3. 关键依据和数据时间；
4. “查看详情”或“继续问 AI”。

个人投顾最多 5 条，专业投研最多 12 条。没有重要变化时明确显示“今日无明显变化”，不填充噪声。

### 5.2 AI 对话

一个输入框覆盖：

- 问市场；
- 问个股；
- 问持仓；
- 做风控；
- 做对比；
- 解释术语和报告。

系统自动选择直接回答、工具调用、多维研究或计划执行。高级用户可调整执行方式，但不要求普通用户理解 Agent 类型。

### 5.3 研究结果

统一结果结构：

1. 一句话结论；
2. 关键依据；
3. 风险与不确定性；
4. 数据来源和时间；
5. 可选的完整四维研究与多空分歧；
6. 推荐继续追问的问题。

### 5.4 持仓与风险

持仓页只保留：

- 成本、数量、当前价格和盈亏；
- 行业集中度；
- 一键询问 AI。

风险页只保留：

- 人话风险结论；
- 金额化影响；
- 主要风险来源；
- 可展开的 VaR、回撤、Sharpe 等专业指标。

### 5.5 新闻

新闻不是通用资讯流，只展示：

- 与持仓相关；
- 与关注行业相关；
- 少量市场级重要事件。

每条新闻支持 AI 解释“为什么相关、可能影响路径、哪些事实仍不确定”。

### 5.6 A 股特色分析因子

A 股分析必须体现中国市场的制度、资金和事件结构，不能只套用美股或通用股票研究模板。

这些因子作为 AI 研究、今日关注、新闻关联和风控解释的检查清单，不作为首屏指标墙。默认展示“影响路径”和“是否已验证”，专业模式可展开证据链、数据来源和缺口。

#### 5.6.1 制度与交易规则

- 涨跌停、连板、炸板、封单强弱；
- ST、退市风险、停复牌、临时停牌；
- T+1、涨跌幅限制、最小交易单位；
- 新股、次新股、注册制/核准制差异；
- 主板、科创板、创业板、北交所规则差异。

#### 5.6.2 资金与筹码

- 主力资金、北向资金、融资融券；
- 龙虎榜、游资席位、机构席位、大宗交易；
- 成交额、换手率、量比、异常放量/缩量；
- 股东户数、筹码集中度、机构持仓变化；
- 行业 ETF 与主题资金流入流出。

#### 5.6.3 供给冲击与股权事件

- 限售股解禁规模、解禁市值占比；
- 大股东减持、增持、质押、被动减持；
- 定增、可转债、回购、分红、送转；
- 并购重组、资产注入、控制权变化；
- 业绩预告、业绩快报、问询函、监管函。

#### 5.6.4 政策、行业与主题

- 宏观政策、产业政策、监管口径变化；
- 部委文件、地方政策、行业补贴；
- 热门主题与板块轮动；
- 龙头、指数、ETF、产业链上下游联动；
- 舆情热度与新闻来源可信度。

#### 5.6.5 财务与质量

- PE、PB、PS、PEG 与行业分位；
- 毛利率、净利率、ROE、经营现金流、应收账款；
- 营收、利润、订单、产能和业绩指引；
- 资产负债率、短债、商誉、存货；
- 财报窗口和业绩兑现风险。

#### 5.6.6 技术与市场结构

- 均线、支撑阻力、突破/跌破；
- ATR、回撤、波动率；
- 相对行业、指数和同类标的的强弱；
- 上涨家数、涨停/跌停家数、赚钱效应；
- 上证指数、沪深300、深证成指、创业板指状态。

#### 5.6.7 输出规则

- 不直接输出买卖、目标价或仓位指令；
- 每个因子必须说明影响的是流动性、情绪、基本面、估值还是事件预期；
- 数据缺失时标注“未验证”，不得由 LLM 补造；
- 普通用户给人话影响，专业用户给证据链和数据缺口；
- 因子相互矛盾时输出多空分歧和置信度。

### 5.7 设置

设置按任务分组：

- AI 模型；
- 数据源；
- 显示模式；
- 分析偏好；
- 本地数据。

隐藏低频技术项，提供合理默认值。

## 6. 信息架构

### 6.1 单画布与顶部视角栏

产品只保留一个主画布，不使用左侧栏，也不把功能拆成多个彼此割裂的传统页面。

大盘指数常驻最顶部。其下方固定一行视角与工具按钮：

`[持仓] [风控] [市场] [新闻·研报]    [AI 对话]`

- **持仓**是默认视角，回答“我的资产今天怎么样”；
- **风控**回答“我的组合可能怎么亏、风险来自哪里”；
- **市场**回答“今天大盘和市场结构处于什么状态”；
- **新闻·研报**同时容纳研究输入与 AI 研究产出；
- **AI 对话**控制全局 AI 面板的展开和收起。

四个主按钮只切换同一画布的内容与当前页面上下文，不创建四套应用外壳。模式切换、数据状态和设置继续放在全局顶栏。

### 6.2 全局 AI 对话

AI 对话在所有画布视角都存在：

- 默认折叠为右侧窄条或按钮，不挤压主页面；
- 展开后占据右侧 380–440px，左侧业务页面仍然保留；
- 小屏时可覆盖画布，不要求移动端专门适配；
- 深度任务可以从 AI 对话转入完整研究工作区。

各页面不重复实现完整聊天框，只提供轻量 AI 动作，例如：

- 持仓：“解释今天的盈亏”或“分析这只股票”；
- 风控：“谁对组合风险贡献最大？”
- 市场：“今天市场为什么这样走？”
- 新闻·研报：“解释这条新闻”或“继续追问这份研报”。

点击动作后统一打开全局 AI 对话，并显式附加页面上下文。

### 6.3 三层上下文

AI 对话只共享应该共享的内容：

1. **长期用户上下文，全局共享**
   - 持仓；
   - 风险偏好和现金流；
   - 个人投顾 / 专业投研模式；
   - 语言、分析偏好和用户明确保存的记忆。

2. **线程上下文，仅在线程内共享**
   - 当前问题和连续追问；
   - 当前研究对象；
   - 已生成的报告和用户确认的信息。

3. **页面上下文，临时且显式附加**
   - 当前选中的股票、新闻、组合或研究报告；
   - 页面切换不会自动永久写入线程；
   - 用户可一键移除；
   - 默认影响下一次提问，发送后可选择继续保留。

AI 对话顶部必须显示：

- 当前线程；
- 长期上下文摘要；
- 页面上下文标签及移除按钮。

### 6.4 视角切换规则

- 视角切换保留当前线程；
- 视角切换不自动改变“它”“这只股票”等代词指向；
- 新视角有可用上下文时，显示“附加当前画布”操作；
- 用户从画布内 AI 动作进入时，自动附加该对象上下文；
- 深度研究创建独立线程，完成后可保留为历史报告；
- 新对话清空线程内容，但不清空长期用户上下文。

### 6.5 复杂能力调用机制

参考近期中文/A 股开源项目的产品趋势，复杂能力不作为一级导航暴露，而是从当前画布和 AI 对话按需调出。

#### 6.5.1 今日简报

- 持仓视角首屏保留“今日与你有关”卡片；
- 默认只展示 1–5 条最重要变化；
- 每条变化可展开完整证据，包括行情、新闻、风险、A 股特色因子；
- 用户可从卡片继续问 AI，自动附加对应上下文；
- 历史简报进入研究记忆，不做独立时间流页面。

#### 6.5.2 轻量研究卡

个股或持仓深度分析默认输出一张轻量研究卡：

- 结论摘要；
- 基本面观点；
- 技术与市场结构观点；
- 新闻/政策/事件观点；
- 风险官观点；
- 数据缺口与下一步验证。

专业用户可展开完整执行过程、数据来源、因子检查状态和多空分歧。普通用户默认只看结论、影响和风险。

#### 6.5.3 专业抽屉

每个视角保留一个“专业展开”入口：

- 持仓：个股因子、行业暴露、研究记忆；
- 风控：VaR、回撤、相关性、压力情景；
- 市场：市场宽度、板块轮动、资金结构；
- 新闻·研报：来源可信度、影响路径、相关持仓；
- AI 对话：工具调用、数据源状态、研究参数。

专业抽屉默认关闭，不影响首屏极简体验。

#### 6.5.4 数据源详情

每个 AI 结论旁边保留轻量来源提示，例如“行情：新浪，新闻：东财，财务：Tushare，可选”。用户点击后可看到：

- 数据源名称；
- 获取时间；
- 实时、延迟、缓存或 Mock 状态；
- 是否发生降级；
- 多源是否冲突；
- 缺失数据对结论的影响。

## 7. Agent 契约

### 输入

- 用户问题；
- 当前模式；
- 持仓上下文；
- 用户明确选择的股票；
- 数据源与模型配置；
- 可选的执行偏好。

### 输出

- `reply`：适合当前模式的结论；
- `cards`：结构化事实和研究结果；
- `intent`：实际执行的任务类型；
- `partial`：是否发生降级；
- `sources/status`：数据来源与状态；
- `llm_usage`：本次模型用量。

### 失败与降级

- 股票歧义：展示候选，不猜；
- 单个数据源失败：使用备用源并标注；
- 单个 Agent 超时：返回已完成维度并标记 partial；
- LLM 未配置：引导进入设置或使用 Mock；
- SSE 中断：保留最近 checkpoint；
- 数据不足：返回“无法判断”和缺失项，不生成伪结论。

## 8. 技术架构要求

- FastAPI 路由只负责协议、依赖和序列化；
- 同步与 SSE 使用同一任务路由、领域执行和最终输出处理；
- SSE 只增加进度事件，不复制业务决策；
- 中立性过滤、术语标记、免责声明处理必须有唯一入口；
- 数据 Provider 返回来源、时间和降级状态；
- 前端 API 按领域拆分，页面状态不集中在单一巨型组件；
- AI 对话状态独立于具体页面，页面只通过显式契约提供临时上下文；
- 页面上下文必须可见、可移除，不能暗中污染线程；
- 卡片使用判别联合类型，不用大范围 `try/catch + type assertion`；
- SQLite schema 变更采用可追踪迁移；
- CI 至少覆盖测试、构建和不会新增的静态检查基线。
- 真实 Provider 通过显式 live integration test 验证，默认单测不因第三方超时随机失败。

### 8.1 数据源改进方案

数据源从“单源可用”升级为“分层、多源、可解释、可降级”。目标不是接入最多数据源，而是让用户知道数据从哪里来、是否可信、是否新鲜、缺了什么。

#### 8.1.1 数据源分层

| 层级 | 目的 | 默认策略 | 可选增强 |
|---|---|---|---|
| L0 Mock | 无网/无 Key 演示 | 内置示例数据 | 明确标注 Mock |
| L1 免费默认源 | 开箱即用 | 新浪 / 东方财富 / 腾讯公开源 | provider 自动降级 |
| L2 Python 聚合库 | 补齐 A 股结构化数据 | AKShare、Baostock、mootdx | 按功能懒加载 |
| L3 用户 Key 源 | 更稳定、更丰富 | 用户自行配置 | Tushare Pro、搜索 API、新闻 API |
| L4 本地缓存 | 稳定和复盘 | SQLite 缓存最近结果 | 离线复盘、研究记忆 |

#### 8.1.2 数据类型与推荐来源

| 数据类型 | MVP 默认 | 增强来源 | 用途 |
|---|---|---|---|
| 指数与实时行情 | 新浪 / 腾讯 / 东方财富 | mootdx | 顶部指数、持仓刷新、市场状态 |
| K 线与技术指标 | 新浪 / 东方财富 | AKShare / mootdx | 趋势、支撑阻力、波动 |
| 财务与估值 | 东方财富 | AKShare / Tushare Pro | 财务质量、估值分位、业绩窗口 |
| 新闻与公告 | 东方财富 / 财联社公开源 | 搜索 API / Tushare 公告 | 新闻·研报、今日关注 |
| 龙虎榜与资金 | 东方财富 | Tushare Pro | 游资、机构席位、资金异动 |
| 解禁、减持、质押 | 东方财富 | Tushare Pro / AKShare | 供给冲击、股权风险 |
| 行业与主题 | 东方财富板块 / AKShare | Tushare Pro | 板块轮动、主题热度 |
| 研究记忆 | 本地 SQLite | 用户导入文档 | 历史观点、复盘和继续追问 |

#### 8.1.3 Provider 契约

每个 provider 必须返回：

- `source`；
- `fetched_at`；
- `latency_ms`；
- `is_cached`；
- `is_mock`；
- `degraded_reason`；
- 可选的 `confidence` 和 `conflict_with`。

Provider 设计要求：

- 同类数据至少支持主备源；
- 高频公开源必须有缓存、限流、随机抖动和 Keep-Alive；
- 数据 schema 以业务对象为中心，不把第三方字段直接暴露给前端；
- 后端可保留原始响应摘要用于 debug，但不作为产品契约；
- live provider 用显式集成测试验证，默认单测不依赖外部服务。

#### 8.1.4 数据可信度

AI 输出的数据状态分为：

- **已验证**：多个来源一致，或来自用户配置的高可信源；
- **单源**：只有一个来源，允许使用但必须标注；
- **延迟**：说明延迟窗口；
- **缓存**：说明缓存时间；
- **冲突**：列出冲突并降低置信度；
- **缺失**：列出缺失项，不让模型补造。

#### 8.1.5 设置体验

设置页只暴露三个层级：

1. **默认真实数据**：无需 Key，使用免费公开源；
2. **增强数据**：用户填入 Tushare Pro、搜索 API、新闻 API 等 Key；
3. **诊断面板**：专业用户查看 provider 状态、失败原因、缓存和限流。

普通用户只需要看到“真实数据 / 缓存 / Mock / 降级”。专业用户可以展开完整来源。

## 9. MVP 范围

必须保留：

- 双模式与首次引导；
- 今日关注；
- AI 对话与流式过程；
- 个股、行业、市场研究；
- 四维研究与可选辩论；
- 持仓、新闻、风险；
- 示例数据与 Mock；
- 本地 LLM 和数据源配置；
- 分层数据源、来源可信度、缓存与降级说明；
- 数据降级提示；
- 中英文界面。

需要重构：

- 同步/SSE 双轨编排；
- 输出后处理不一致；
- 前端根组件、API 和卡片渲染过度集中；
- AI 对话只存在于单一页面，其他页面仍接近传统信息页面；
- 数据库迁移；
- PRD、README 和真实实现状态不一致；
- 静态检查未形成有效门禁。

## 10. 非目标

- 不上线为公网 SaaS；
- 不做注册、登录、多用户、权限和计费；
- 不做交易下单、自动调仓或券商连接；
- 不做全市场扫描器和传统终端式功能矩阵；
- 不做 Level-2、盘口、复杂技术指标库；
- 不做社区、跟单、排行榜；
- 不做移动端优先和 PWA；
- 不做复杂动画、3D 图表、游戏化；
- 不做独立时间流、收件箱或任务管理视图；
- 不为展示 Agent 数量而增加 Agent；
- 不追求覆盖所有数据源和所有市场。

## 11. 验收标准

- `.prd/PRD.md` 与 `docs/PRD.md` 产品边界一致；
- 普通和流式聊天共享最终输出处理，并且只产生一个最终 `done`；
- 两条聊天路径都有一致性测试；
- 核心功能测试全部通过；
- 前端生产构建通过；
- CI 明确运行后端测试、前端测试和构建；
- README 不再把项目描述为终端或未来 SaaS；
- 四个主视角均可打开同一个 AI 对话；
- 视角切换保留线程但不会隐式替换页面上下文；
- 页面上下文在 AI 对话顶部可见且可移除；
- 大盘指数和五个顶部按钮在四个主视角中保持位置不变；
- AI 结论可查看数据来源、时间、缓存、Mock、降级与冲突状态；
- A 股因子检查可展开查看每个因子的 provider、层级、验证状态和缺失来源；
- 未新增任何非目标功能。
