# 投小宝 PRD（Product Requirement Document）

> 版本：V1.0 | 日期：2026-05-27 | 产品定位：面向个人投资者的 A 股 AI 投研助手

---

## 一、产品概述

### 1.1 产品定位

**投小宝** 是一款面向个人投资者的 A 股 AI 投研助手，以 Multi-Agent 架构为核心，整合实时新闻分析、AI 投研、智能风控、自然语言对话四大能力，帮助个人投资者在海量信息中快速获取结构化、可操作的决策参考。

### 1.2 产品愿景

让每一个 A 股个人投资者都拥有一个「AI 投研团队」——一个会读新闻、会看财报、会算风险、会说人话的智能助手。

## 二、用户分析

### 2.1 核心用户画像

| 属性 | 描述 |
|------|------|
| 人群 | 25-45 岁，有 A 股投资经验 1 年以上 |
| 持仓 | 通常持有 3-15 只股票，总资产 5-200 万 |
| 信息获取 | 雪球、东方财富、同花顺、公众号、抖音财经博主 |
| 核心痛点 | 信息过载但噪音多；想深入研究但没时间/没能力；追涨杀跌缺乏纪律 |
| 核心需求 | 快速知道「发生了什么 + 对我有什么影响 + 我该怎么办」 |

### 2.2 用户场景地图

```
早 9:00  开盘前 → 想知道昨夜外盘、今早政策/公告，我的持仓会怎么走
         → 触发：每日开盘简报（新闻分析 Agent）
         
早 9:30  盘中 → 某只持仓股突然大跌 5%，想立刻知道原因
         → 触发：异动预警 + 实时归因（新闻分析 + 风控 Agent）

午 12:00 午间 → 想看看上午市场整体风格（哪个板块强、资金在做什么）
         → 触发：午间市况简报（投研 Agent）

晚 20:00 复盘 → 今天操作回顾，持仓风险评估，明天计划
         → 触发：复盘日报 + 风控体检（投研 + 风控 Agent）

周末     深度 → 想系统了解一个行业/赛道，选几只备选股
         → 触发：行业深度分析（投研 Agent 多轮研究）
```

### 3.2 Agent 详细定义

#### Agent 1：新闻分析 Agent（实时）

| 属性 | 说明 |
|------|------|
| 定位 | 7×24 小时监控 A 股相关信息流，实时分析并推送对用户持仓的影响 |
| 触发方式 | 主动监控 + 用户查询 |
| 输入 | 新闻流（财联社/华尔街见闻/巨潮资讯）、公告流（交易所）、社交媒体热帖（雪球/股吧） |
| 处理流程 | 获取新闻 → 实体识别（哪只股票/哪个行业） → 情感分析（利好/利空/中性） → 影响评估（短期情绪/基本面变化/政策信号） → 结构化为卡片 |
| 输出 | 新闻卡片（标题 + 一句话摘要 + 影响标签 + 关联持仓提示） |
| 工具集 | 新闻 API、公告爬虫、NLP 情感模型 |

**关键设计**：

- **噪音过滤**：A 股每天数千条新闻，90% 是噪音。Agent 内置三层过滤——关键词黑名单（如「暴涨」「惊爆」等标题党词汇降权）、信源权威性打分、与用户持仓相关度排序。
- **速度优先于深度**：新闻 Agent 的目标是「1 分钟内告诉你发生了什么」，深度分析交给投研 Agent。所以这个 Agent 不调用 LLM 做长篇推理，只用轻量模型做分类 + 摘要，延迟控制在 3 秒内。

#### Agent 2：投研分析 Agent（深度）

| 属性 | 说明 |
|------|------|
| 定位 | 模拟买方研究员的工作流，对个股/行业做深度分析 |
| 触发方式 | 用户主动发起 + 定时任务（每日/每周简报） |
| 子 Agent | 基本面 Agent、技术面 Agent、情绪面 Agent、筹码面 Agent |
| 输出 | 结构化投研报告（HTML/卡片），包含多空辩论过程 |

**四个子 Agent 详细设计**：

| 子 Agent | 分析维度 | 数据源 | 核心 Prompt 片段 |
|----------|---------|--------|-----------------|
| 基本面 Agent | 营收增速、毛利率、ROE、PE 分位、现金流、商誉等 | 财报 API、Wind/Choice 轻量接口 | 「你是一位价值投资者，请从以下财务数据中找出最关键的 3 个亮点和 3 个风险点，逐一说明理由」 |
| 技术面 Agent | MA/MACD/RSI/布林带、量价关系、支撑压力位 | 行情 API | 「你是一位技术分析师，请分析当前 K 线形态，指出关键支撑位和压力位，并判断短期趋势方向」 |
| 情绪面 Agent | 雪球讨论热度、股吧帖子情感、新闻舆情综合打分 | 社交媒体 API + NLP | 「你是一位市场情绪分析师，请综合以下讨论数据，判断市场对该股的情绪是过度乐观、过度悲观还是中性」 |
| 筹码面 Agent | 龙虎榜、北向资金、主力资金流向、股东户数变化 | 东方财富 API | 「你是一位筹码分析专家，请分析近期资金动向，判断主力是在吸筹、出货还是观望」 |

**多空辩论机制**：

```
Step 1：四个子 Agent 独立分析，各自输出结构化结论 + 置信度
Step 2：编排引擎将四个结论汇总，模拟两轮辩论：
         Round 1 — 看多论点 vs 看空论点逐一对抗
         Round 2 — 裁判 Agent 评估各论点论据质量，给出综合倾向
Step 3：输出最终报告，包含「共识结论」「核心分歧」「置信度标注」
```

**面试可讲的设计亮点**：辩论机制不是炫技，而是解决个人投资者的「确认偏误」——散户天然倾向于只看支持自己持仓的信息。强制展示多空双方论据，让用户自己做判断，比给一个武断的建议更负责任。

#### Agent 3：风控 Agent（实时）

| 属性 | 说明 |
|------|------|
| 定位 | 用户的「AI 风控官」，实时监控持仓风险，提供止损/止盈建议 |
| 触发方式 | 盘中每 5 分钟轮询 + 用户查询 + 关键事件触发 |
| 输入 | 用户持仓数据、实时行情、大盘状态、个股新闻 |
| 输出 | 风险预警卡片、止损建议、仓位评估 |

**风控维度**：

| 风控维度 | 具体规则 | 预警阈值 |
|----------|---------|---------|
| 个股止损 | 单只股票从持仓成本回撤 | 跌超 8% → 黄色预警；跌超 15% → 红色预警 |
| 个股止盈 | 单只股票盈利回吐 | 从最高点回撤超 10% → 建议减仓 |
| 仓位集中度 | 单一行业/板块占比 | 超 40% → 提示集中度风险 |
| 大盘联动 | 持仓与沪深 300 相关性 | 大盘暴跌 2%+ 且持仓同向 → 系统性风险提示 |
| 黑天鹅 | 财报暴雷、ST 风险、退市风险、财务造假嫌疑 | 实时监控，命中即推送 |
| 连续止损 | 最近 5 笔交易胜率 | 低于 30% → 建议暂停交易冷静 |

**面试可讲的设计亮点**：

- **熔断机制（Kill Switch）**：借鉴 NoFx 的设计，当用户连续止损 3 次以上时，风控 Agent 主动建议「暂停交易 24 小时」，并在对话中用温和但坚定的语气劝阻冲动交易。这不是技术问题而是产品伦理问题——AI 应该帮用户控制损失，而不是鼓励频繁交易赚佣金。
- **风险语言化**：不用 VaR、CVaR 等专业术语，而是翻译成人话——「你的持仓整体来看，如果大盘跌 5%，你大概会亏 8%，这个风险水平偏高了，建议把仓位降到 6 成」。

#### Agent 4：对话沟通 Agent（全时段）

| 属性 | 说明 |
|------|------|
| 定位 | 用户与投小宝的唯一对话入口，负责意图识别、任务分发、结果呈现 |
| 触发方式 | 用户主动输入 + 系统主动推送 |
| 输入 | 用户自然语言消息 |
| 输出 | 对话回复（文字 + 卡片） |

**核心能力**：

1. **意图路由**：识别用户意图，分发给对应 Agent
   - 「茅台今天怎么了」→ 新闻分析 Agent（实时归因）
   - 「帮我分析一下宁德时代值不值得买」→ 投研分析 Agent（多子 Agent 协作）
   - 「我的持仓现在风险大吗」→ 风控 Agent（组合体检）
   - 「什么是 MACD 金叉」→ 对话 Agent 直接回答（知识库）

2. **多轮对话**：记住上下文，支持追问和深入
   - 用户：「茅台怎么样」
   - 投小宝：输出投研简报
   - 用户：「那五粮液呢」
   - 投小宝：输出五粮液简报，并自动追加「与茅台对比」段落

3. **主动推送**：不是等用户问，而是在关键事件发生时主动告知
   - 持仓股异动 → 推送预警卡片
   - 每日 9:00 → 推送开盘简报
   - 用户关注的行业有重大新闻 → 推送分析

**面试可讲的设计亮点**：「Push > Chat」——对于个人投资者，信息获取的第一需求不是「我想问的时候能问」，而是「我不知道该问的时候，AI 替我发现该知道的事」。这也是 FinGenius 和 daily_stock_analysis 两个项目验证过的方向。

### 3.3 编排引擎（Orchestrator）设计

编排引擎是整个 Multi-Agent 架构的中枢，负责协调多个 Agent 协作完成任务。

**核心流程**：

```
用户输入
  ↓
意图识别（路由到对应 Agent 组合）
  ↓
任务拆解（将复杂问题拆为子任务）
  ├── 子任务 A → 新闻分析 Agent
  ├── 子任务 B → 投研分析 Agent（触发 4 个子 Agent）
  └── 子任务 C → 风控 Agent
  ↓
结果聚合
  ├── 冲突检测：不同 Agent 结论矛盾？（如基本面 Agent 看多、技术面 Agent 看空）
  ├── 矛盾处理：触发辩论 → 裁判 Agent 仲裁
  └── 统一输出：生成结构化回复
  ↓
交付给对话 Agent → 呈现给用户
```

**关键设计原则**：

1. **并行的尽量并行**：新闻、投研、风控三个 Agent 如果没有数据依赖，同时调用，减少用户等待。
2. **依赖的顺序执行**：投研 Agent 内部四个子 Agent 并行分析后，再进入辩论阶段（串行）。
3. **超时降级**：任何 Agent 超过 15 秒未返回，跳过该 Agent 的结果，其他 Agent 结果正常输出并在底部标注「部分分析未完成」。

## 四、功能模块详细设计

### 4.1 模块一：实时新闻分析整合

#### 功能清单

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 全市场快讯流 | 实时推送 A 股相关新闻，按时间线排列 | P0 |
| 持仓关联过滤 | 只显示与我持仓相关的新闻 | P0 |
| 新闻影响标签 | 每条新闻打标：利好/利空/中性 + 影响级别（重大/一般/噪音） | P0 |
| AI 一句话解读 | 每条新闻附 AI 生成的一句话解读 | P0 |
| 异动归因 | 持仓股涨跌幅超 3% 时，自动分析可能原因 | P1 |
| 盘前简报 | 每日 9:00 生成开盘必读简报 | P1 |
| 行业轮动监控 | 实时展示当日资金流入/流出最多的行业板块 | P2 |

#### 新闻分析流程图

```
数据采集（财联社 RSS + 华尔街见闻 + 巨潮公告 + 雪球热帖）
    ↓
实体识别（NER：提取股票代码、行业标签、人物、政策关键词）
    ↓
去重 & 聚合（同一事件多家媒体报道合并为一条）
    ↓
情感分析（FinBERT 中文金融情感模型打分）
    ↓
用户持仓匹配（新闻涉及股票 ∩ 用户持仓 → 标记「与你相关」）
    ↓
AI 摘要生成（轻量 LLM 生成一句话解读，< 2 秒）
    ↓
推送 / 展示
```

### 4.2 模块二：AI 投研

#### 功能清单

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 个股深度分析 | 单只股票的四维分析（基本面 + 技术面 + 情绪面 + 筹码面）+ 多空辩论 | P0 |
| 行业赛道分析 | 按申万行业分类，分析整个赛道的竞争格局和投资机会 | P1 |
| 每日复盘报告 | 盘后自动生成：今日市场总结 + 持仓表现 + 明天关注要点 | P0 |
| 每周深度报告 | 周末生成：本周复盘 + 下周展望 + 精选标的池 | P1 |
| 智能选股 | 用户说「帮我找高股息、PE<15、市值>500亿的公司」→ 自动筛选 | P1 |
| 研报速读 | 用户上传/粘贴券商研报，AI 提取核心观点和关键数据 | P2 |
| 财报解读 | 财报发布后自动生成白话版解读 + 关键指标历史对比 | P1 |

#### 投研输出规范

所有投研输出必须包含：

1. **置信度标注**：高/中/低，让用户知道 AI 对结论的确信程度
2. **多空双方观点**：即使倾向看多，也必须展示看空方的核心论据
3. **免责声明**：「以上内容由 AI 生成，仅供参考，不构成投资建议」
4. **数据来源**：标注每条关键数据的出处（如「数据来源：2025 年年报」）

### 4.3 模块三：智能风控

#### 功能清单

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 持仓体检 | 一键分析当前持仓的集中度、估值、回撤等风险指标 | P0 |
| 止损提醒 | 个股从成本价回撤超阈值时推送预警 | P0 |
| 止盈建议 | 盈利大幅回吐时建议锁定利润 | P1 |
| 仓位建议 | 根据大盘状态（牛/熊/震荡）给出仓位区间建议 | P1 |
| 黑天鹅预警 | 财报变脸、ST 风险、立案调查等重大利空实时监控 | P0 |
| 交易纪律 | 连续止损 3 次后触发「冷静期」建议 | P2 |
| 压力测试 | 「如果大盘跌 10%，我的持仓会怎样」模拟 | P2 |

#### 风控产品设计原则

1. **不替用户做决定，但替用户算清楚账**：风控 Agent 不会说「立即卖出」，而是说「你以 50 元买入，现价 42 元，已亏损 16%。如果你在买入时设了 15% 止损线，按照纪律现在应该执行止损。是否要设止损单？」
2. **追溯用户自己的规则**：引导用户在初期设定自己的风控规则（止损线、仓位上限、行业集中度上限），之后 AI 只需要提醒「你自己定的规则被触发了」，比 AI 替用户定规则更有说服力。

### 4.4 模块四：AI 对话沟通

#### 功能清单

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 自然语言问答 | 支持任意金融相关问题，自动路由到对应 Agent | P0 |
| 多轮对话 | 保持上下文，支持追问和深入 | P0 |
| 主动推送 | 持仓异动、市场大事、每日简报主动推送 | P0 |
| 投资教育对话 | 用户问「什么是 PB」「怎么读财报」时用通俗语言解释 | P2 |

| 对话历史 | 保存历史对话，支持搜索回溯 | P1 |

#### 对话 Agent 的 System Prompt 核心规则

```
你是「投小宝」，一个面向 A 股个人投资者的 AI 投研助手。
核心原则：
1. 永远不给出「买入」「卖出」的确定性建议，只提供分析和参考
2. 每次分析必须同时展示多空双方的核心论据
3. 使用白话，不用专业术语堆砌，假设用户是金融小白
4. 所有结论必须标注置信度（高/中/低）和数据来源
5. 涉及风险时语气可以严肃但不制造恐慌
6. 用户情绪激动时先安抚再分析（「理解你的心情，我们先看看数据怎么说」）
7. 每次回复末尾固定标注「以上内容由 AI 生成，仅供参考」
```

### 5.2 技术选型详解

#### 5.2.1 Agent 框架 —— AutoGen

| 项目 | 选型 | 理由 |
|------|------|------|
| 核心框架 | **AutoGen（微软）** | 微软官方 Multi-Agent 框架，原生支持 GroupChat、辩论模式、工具调用、人机协作 |
| Agent 通信 | AutoGen GroupChat | 多 Agent 在同一个对话上下文中轮流发言，天然适配「四子 Agent 并行分析 → 辩论 → 裁判裁决」的投研流程 |
| 辩论实现 | AutoGen RoundRobinGroupChat + CustomSelector | 自定义发言顺序：四个分析师依次发言 → 进入辩论轮次 → 裁判 Agent 总结 |
| 工具调用 | AutoGen ToolAgent + Function Calling | 每个 Agent 注册自己的工具函数（行情查询、财报解析、新闻搜索），AutoGen 自动按需调度 |
| 人机协作 | AutoGen UserProxyAgent | 风控 Agent 触发高风险预警时，通过 UserProxyAgent 暂停流程、弹出人工确认卡片 |

**AutoGen 实现投研 Agent 的核心代码结构**：

```python
from autogen import AssistantAgent, GroupChat, GroupChatManager

# 四个子 Agent 定义
fundamental_analyst = AssistantAgent(
    name="基本面分析师",
    system_message="你是A股价值投资分析师，从财务数据中挖掘关键信息...",
    llm_config={"config_list": azure_gpt4o_config},
    tools=[query_financials, query_valuation]  # 注册工具函数
)

technical_analyst = AssistantAgent(
    name="技术面分析师",
    system_message="你是技术分析师，分析K线形态与量价关系...",
    llm_config={"config_list": azure_gpt4o_config},
    tools=[query_kline, calc_indicators]
)

sentiment_analyst = AssistantAgent(
    name="情绪面分析师",
    system_message="你是市场情绪分析师，综合舆情数据判断情绪...",
    llm_config={"config_list": azure_gpt4o_config},
    tools=[query_social_sentiment, query_news_sentiment]
)

position_analyst = AssistantAgent(
    name="筹码面分析师",
    system_message="你是筹码分析专家，追踪主力资金动向...",
    llm_config={"config_list": azure_gpt4o_config},
    tools=[query_capital_flow, query_dragon_tiger]
)

# 裁判 Agent
judge = AssistantAgent(
    name="裁判",
    system_message="你评估各分析师的论据质量，给出综合倾向与置信度...",
    llm_config={"config_list": azure_gpt4o_config}
)

# 创建 GroupChat 辩论流程
groupchat = GroupChat(
    agents=[fundamental_analyst, technical_analyst, 
            sentiment_analyst, position_analyst, judge],
    messages=[],
    max_round=8,  # 四分析师发言 + 2轮辩论 + 裁判总结
    speaker_selection_method="round_robin"  # 轮流发言保证公平
)

manager = GroupChatManager(groupchat=groupchat)
```

#### 5.2.2 大模型 —— Azure OpenAI Service

| 场景 | 模型选择 | 理由 |
|------|---------|------|
| 新闻分类 / 情感分析 | GPT-4o-mini | 轻量、低延迟（< 2 秒）、成本为 GPT-4o 的 1/20 |
| 投研深度分析 | GPT-4o | 128K 上下文窗口，可一次读入完整财报 + 多份研报，推理能力强 |
| 多空辩论 | GPT-4o | 辩论需要高推理质量，错误成本高 |
| 对话 Agent | GPT-4o-mini（路由）+ GPT-4o（复杂问答） | 简单意图识别用轻量模型，复杂投研问答升级到 GPT-4o |
| 嵌入向量 | text-embedding-3-large | 财报、研报、新闻的向量化存储与 RAG 检索 |

**成本控制**：Azure OpenAI 提供预置吞吐量（PTU），可按月购买预留算力，单 token 成本比按量付费低 40-60%。投研类高消耗场景使用 PTU，轻量场景使用按量付费。

#### 5.2.3 RAG 检索 —— Azure AI Search

| 组件 | 选型 | 说明 |
|------|------|------|
| 搜索引擎 | **Azure AI Search** | 微软原生向量 + 关键词混合检索，支持金融分词和中文语义理解 |
| 数据源索引 | 财报 PDF、券商研报、历史新闻、交易所公告 | 通过 Azure AI Search 内置的文档解析 + 分块 + 向量化管道自动入库 |
| 检索策略 | 混合检索（Hybrid Search） | 向量语义检索 + BM25 关键词检索融合，解决金融领域专有名词（如「商誉减值」「非经常性损益」）的精确匹配问题 |
| 实时更新 | Azure Functions 触发器 | 新财报/公告发布 → Azure Functions 触发 → 自动解析 → 增量更新索引 |

#### 5.2.4 AI 编排与插件 —— Semantic Kernel

| 用途 | 说明 |
|------|------|
| 对话 Agent 的意图路由 | 使用 Semantic Kernel 的 Planner 自动将用户自然语言拆解为多步函数调用链 |
| 金融工具插件 | 将行情查询、财报解析、新闻搜索封装为 SK Plugin，对话 Agent 自动按需调用 |
| 记忆管理 | Semantic Kernel 的 Memory Store 管理用户短期对话上下文和长期投资偏好 |
| 与 AutoGen 配合 | Semantic Kernel 作为 Agent 的「工具箱」层，AutoGen 作为 Agent 的「协作」层 |

**Semantic Kernel 意图路由示例**：

```python
import semantic_kernel as sk

kernel = sk.Kernel()
# 注册金融工具插件
kernel.add_plugin(StockQueryPlugin(), "stock")
kernel.add_plugin(NewsAnalysisPlugin(), "news")
kernel.add_plugin(RiskControlPlugin(), "risk")
kernel.add_plugin(ResearchPlugin(), "research")

# Planner 自动拆解用户意图
# 用户输入：「茅台最近有什么利空，我的持仓风险大吗」
# Planner 自动生成执行计划：
#   1. news.search("茅台 利空") → 新闻分析Agent
#   2. risk.portfolio_check(user_id) → 风控Agent
#   3. 聚合结果输出
```

## 七、指标体系

### 7.1 北极星指标

**周活跃用户中有持仓分析行为的用户占比**——衡量用户是否真正用投小宝辅助投资决策，而非只是偶尔聊天。

### 7.2 核心指标

| 指标 | 目标（Phase 1） | 目标（Phase 2） |
|------|----------------|----------------|
| 次日留存率 | > 35% | > 45% |
| 7 日留存率 | > 20% | > 30% |
| 人均日对话轮次 | > 3 | > 5 |
| 投研报告生成量（日） | > 500 | > 2000 |
| 风控预警点击率 | > 40% | > 50% |
| 新闻卡片点击率 | > 25% | > 35% |
| 持仓录入率（注册用户中） | > 50% | > 70% |

### 7.3 关键漏斗

```
下载注册 → 首次对话 → 录入持仓 → 首次投研分析 → 
首次风控体检 → 次日回访 → 连续 7 天活跃 → 付费转化
```

每个环节都需要埋点优化，尤其是「录入持仓」——如果用户不录入持仓，新闻过滤和风控都无法个性化，产品价值大打折扣。Phase 1 需要设计强引导流程（如首次对话后自动提示「录入持仓可以获得更精准的分析」）。

## 八、风险与应对

| 风险 | 概率 | 影响 | 应对 |

### B. 关键 Prompt 示例

**投研 Agent - 基本面子 Agent 的 System Prompt**：

```
你是一位资深 A 股价值投资分析师，擅长从财务报表中挖掘关键信息。
你的分析风格：理性、数据驱动、不追热点。

分析步骤：
1. 先看营收和利润趋势（近 3 年 CAGR）

输出格式：
- 每点用一句话概括 + 一个关键数据支撑
- 最后给出综合评分（1-10 分，含置信度）
- 标注所有数据的来源和时间
- 必须在末尾标注「以上分析由 AI 生成，仅供参考」
```
