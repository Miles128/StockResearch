## 一、规划摘要

### 1.1 项目定位

投小宝是一款面向 **A 股个人投资者** 的 Multi-Agent 投研助手，核心闭环：

```
数据采集 → 多 Agent 分析 → 风控兜底 → 对话呈现
```

与竞品差异点（来自 PRD + 行业对标）：

| 维度 | 行业常见做法 | 投小宝策略 |
|------|-------------|-----------|
| 投研输出 | 单 Agent 直接给结论 | **Research-Battle 双阶段**（FinGenius）+ 多空辩论（TradingAgents） |
| 角色设计 | 通用金融 Agent | **A 股原生四维**（基本面/技术面/情绪面/筹码面） |
| 风控 | VaR 等专业指标 | **规则引擎 + 人话翻译** + Kill Switch（NoFx） |
| 合规 | 事后审核 | **输出端强制标注** + 不做买卖建议（Anthropic Draft 哲学） |
| 成本 | 全量大模型 | **模型分级 + 缓存 + 预生成**（FinRobot 感知-大脑-行动分层） |

### 1.2 开发周期总览

| 阶段 | 周期 | 目标 | 可演示里程碑 |
|------|------|------|-------------|
| **Phase 0** 基础平台 | 3 周 | 数据层 + Agent 骨架 + 对话入口 | 能问「茅台怎么样」并返回结构化卡片 |
| **Phase 1** MVP | 5 周 | PRD Phase 1 全量功能 | 新闻→投研→风控→对话闭环 |
| **Phase 2** 深度体验 | 8 周 | 辩论、推送、行业分析 | 主动推送 + 多空辩论报告 |
| **Phase 3** 生态完善 | 8 周 | 付费、社区、教育 | 商业化闭环 |

**总计：约 6 个月**（与 PRD 路线图一致，Phase 0 为新增的工程奠基期）

### 1.3 北极星指标

**周活跃用户中有持仓分析行为的用户占比** —— 所有开发优先级以此为准。

Phase 1 关键漏斗：`注册 → 首次对话 → 录入持仓 → 首次投研 → 首次风控 → 次日回访`

## 二、PRD 分析与行业对标映射

### 2.1 架构分层（FinRobot 感知-大脑-行动 → 投小宝实现）

```
┌─────────────────────────────────────────────────────────┐
│  行动层（Action）    Web/小程序 + 卡片 UI + 主动推送      │
├─────────────────────────────────────────────────────────┤
│  大脑层（Brain）     Orchestrator + 4 Agent + 辩论/裁判   │
├─────────────────────────────────────────────────────────┤
│  感知层（Perception）行情/新闻/公告/财报/社交 多源采集      │
└─────────────────────────────────────────────────────────┘
```

### 2.2 四大 Agent 与行业参考对照

| 投小宝 Agent | PRD 职责 | 行业参考 | 关键借鉴点 |
|-------------|---------|---------|-----------|
| 新闻分析 | 实时、3 秒内、轻量模型 | FinRobot 感知层 | 不用 LLM 长篇推理；FinBERT + 规则过滤 |
| 投研分析 | 四维子 Agent + 辩论 | TradingAgents + FinGenius | **独立研究 → 再辩论**；工具集隔离 |
| 风控 | 规则引擎 + 人话 | CrewAI 流水线 + NoFx | 量化计算用代码，LLM 只做语言化 |
| 对话 | 意图路由 + 呈现 | Anthropic 9 Agent + Dexter | 专用 Agent 边界清晰；Planner 拆解复杂问题 |

### 2.3 必须落地的 5 条设计原则

1. **视角隔离**：基本面 Agent 只能调财报 API，技术面只能调 K 线——禁止跨域污染（TradingAgents）
2. **Research 先于 Battle**：四子 Agent 并行完成后再进入辩论，避免信息不全就开辩（FinGenius）
3. **Draft 哲学**：所有输出带置信度、数据来源、免责声明；永不输出「买入/卖出」（Anthropic）
4. **Push > Chat**：Phase 2 起主动推送是留存核心，MVP 预留推送基础设施
5. **混合编排**：分类/情感/风控阈值用 `if-else` + 规则引擎；LLM 只做推理与语言化（AGENTS.md + 度小满实践）

### 3.3 技术选型（与 PRD 对齐 + 工程约束）

| 层级 | 选型 | 理由 |
|------|------|------|
| 后端 | Python 3.12 + FastAPI | 金融生态、Agent 框架成熟 |
| Agent 编排 | **LangGraph** | 有状态多步、并行/串行、超时降级 |
| 数据库 | PostgreSQL + Redis | 用户/持仓/对话持久化 + 缓存/会话 |
| 向量库 | **Chroma**（MVP）→ Milvus（Phase 2） | MVP 轻量，后期规模化 |
| 任务队列 | Celery + Redis Beat | 定时简报、风控轮询、新闻抓取 |
| LLM | DeepSeek-V3 / Qwen（主）+ OpenAI 兼容（备） | 成本 + 合规 |
| 情感/NLP | FinBERT-cn / 轻量分类模型 | 新闻 Agent 3 秒 SLA |
| 前端 | **React + Vite**（MVP Web） | 迭代快；App/小程序 Phase 2 |
| 部署 | Docker Compose（MVP）→ K8s（Phase 3） | 渐进式 |

### 3.4 Orchestrator 核心流程（LangGraph 状态机）

```python
# 伪代码 — 实现参考
State = {
    "user_input": str,
    "intent": Literal["news", "research", "risk", "chat", "composite"],
    "symbols": list[str],
    "agent_results": dict,
    "final_response": str,
}

# 图结构
START → intent_router → [并行] news_agent | research_agent | risk_agent
                      → aggregate → (conflict?) debate_judge → chat_format → END

# MVP 简化：research 阶段用 vote 代替 debate；Phase 2 启用 debate_judge
```

**超时降级**：单 Agent 15s 超时 → 跳过并在响应底部标注「部分分析未完成」。

## 四、分阶段开发计划

### Phase 0：基础平台（Week 1–3）

**目标**：数据能进来、Agent 能跑、对话能通。

| 周次 | 任务 | 交付物 | 验收标准 |
|------|------|--------|---------|
| W1 | 项目脚手架、CI、异常体系、用户/持仓 CRUD | `pyproject.toml`、基础 API、pytest 绿 | 用户注册、录入 3 只持仓 |
| W1 | 行情 Provider（新浪/东财免费接口） | `data/providers/quotes.py` | 实时报价延迟 < 5s |
| W2 | 新闻 Provider（财联社 RSS + 巨潮公告） | 新闻入库 Pipeline | 1 分钟级新新闻入库 |
| W2 | NER + 去重 + FinBERT 情感 | `data/pipeline/news.py` | 实体识别准确率人工抽检 > 80% |
| W3 | LangGraph 骨架 + Intent Router | `orchestrator/graph.py` | 4 类意图路由准确率 > 90%（测试集） |
| W3 | 对话 Agent + SSE 流式 | `/chat` API + Web 聊天页 | 端到端对话 < 3s（纯 chat） |

**Phase 0 不做**：辩论、推送、App。

### Phase 1：MVP 闭环（Week 4–8，对应 PRD Phase 1）

**目标**：新闻 → 分析 → 风控 → 对话，被动查询全通。

#### Sprint 1（W4–5）：新闻 + 投研

| 模块 | 功能 | 实现要点 |
|------|------|---------|
| 新闻 Agent | 全市场快讯流、持仓过滤、影响标签、一句话解读 | 轻量 LLM 摘要；关键词黑名单降权 |
| 投研 Agent | 四维并行分析 + **简版报告（投票聚合，无辩论）** | 4 子 Agent 各独立 Prompt + 工具集 |
| 缓存 | 同股 24h 投研缓存 | Redis key: `research:{symbol}:{date}` |

**投研子 Agent 工具集隔离**：

| 子 Agent | 允许调用的 Tool |
|---------|----------------|
| fundamental | `get_financials`, `get_valuation`, `get_industry_peers` |
| technical | `get_kline`, `calc_ma`, `calc_macd_rsi` |
| sentiment | `get_xueqiu_hot`, `get_news_sentiment_score` |
| chips | `get_dragon_tiger`, `get_northbound_flow`, `get_holder_count` |

#### Sprint 2（W6–7）：风控 + 对话增强

| 模块 | 功能 | 实现要点 |
|------|------|---------|
| 风控 Agent | 持仓体检、止损提醒、黑天鹅预警 | **规则引擎**（非 LLM 算阈值）；LLM 仅做「人话翻译」 |
| 对话 Agent | 多轮上下文、意图分发、卡片呈现 | Redis 会话；结构化 JSON → 前端卡片组件 |
| 引导流程 | 首次对话后引导录入持仓 | 漏斗埋点：`onboarding_holdings_prompt_shown` |

**风控规则引擎（MVP 硬编码，Phase 3 用户自定义）**：

```yaml
rules:
  - id: stop_loss_yellow
    condition: drawdown_from_cost > 0.08
    severity: yellow
  - id: stop_loss_red
    condition: drawdown_from_cost > 0.15
    severity: red
  - id: concentration
    condition: single_sector_weight > 0.40
    severity: warning
  - id: black_swan
    trigger: [st_risk, fraud_alert, delisting_notice]
    severity: critical
```

### Phase 2：深度体验（Week 9–16，对应 PRD Phase 2）

| Sprint | 功能 | 行业参考 | 关键技术 |
|--------|------|---------|---------|
| S4 | **多空辩论 + 裁判 Agent** | TradingAgents 2-3 轮辩论 | LangGraph 串行 debate 节点 |
| S4 | 投研报告 HTML 模板 | FinGenius Research-Battle | Jinja2 + 前端 iframe |
| S5 | **主动推送**：异动预警、盘前简报、盘后复盘 | Push > Chat | Celery Beat + WebSocket/小程序订阅 |
| S5 | 异动归因（涨跌幅 > 3%） | 新闻 + 行情联动 | 事件触发器 |
| S6 | 行业赛道分析 + 智能选股 | Dexter Planner | NL → 筛选条件 → SQL/因子 |
| S6 | 财报解读（触发式） | FinRobot 行动层 | 公告监听 → RAG 财报段落 |
| S7 | 记忆系统：用户偏好 + 长对话 | 度小满 RAG + 知识图谱 | Milvus + 用户画像表 |
| S8 | 对话历史搜索 + 性能优化 | — | 全文检索、报告预生成 |

**辩论机制实现（Phase 2 核心）**：

```
Round 0: 4 子 Agent 并行 → 结构化结论 + confidence
Round 1: Bull Agent 汇总看多论据 ↔ Bear Agent 汇总看空论据（各 1 轮）
Round 2: Judge Agent 评估论据质量 → 综合倾向 + 核心分歧
Output: 报告含「共识结论」「核心分歧」「置信度」三节
```

## 六、模型与成本控制

### 6.1 模型分级策略

| 任务 | 模型 | 预期延迟 | 成本占比 |
|------|------|---------|---------|
| 意图识别 | 7B 分类 / 规则 | < 200ms | 5% |
| 新闻情感 | FinBERT | < 500ms | 0%（本地） |
| 新闻摘要 | 7B（Qwen2.5-7B） | < 2s | 15% |
| 投研子 Agent | 32B / DeepSeek-V3 | 5–10s/个 | 50% |
| 辩论/裁判 | DeepSeek-V3 | 10–15s | 20% |
| 对话/人话翻译 | 7B–32B 按场景 | 1–3s | 10% |

### 6.2 降本手段

1. **24h 投研缓存**：同股重复查询命中缓存
2. **定时预生成**：盘前简报、复盘在低峰（6:00–8:00）批量跑
3. **分层输出**：免费用户看摘要；Pro 看完整辩论过程
4. **单用户日限额**：免费 10 次深度投研 / 天
