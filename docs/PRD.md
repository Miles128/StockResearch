# StockResearch 产品需求文档

**版本：V9.0 · 开源 A 股市场研究 Agent**

> 本文件是 StockResearch 的单一产品需求来源。`docs/DEVELOPMENT_PLAN.md` 已废弃；工程参考见 **§十五 工程附录**。

## 一、产品定位

StockResearch 是一个**开源的 A 股市场研究 Agent**，在本机联网运行。

它不连接券商，不替用户交易，也不提供买卖建议。项目面向 A 股投资者，用多 Agent 研究、分层数据源和 AI 原生交互，帮助理解「今天市场发生了什么、为什么与我有关、还需要验证什么」。代码开源，可 fork、可自部署，数据留在本机。

一句话定义：

> 用 AI 帮用户理解“今天发生了什么、为什么与我有关、还需要验证什么”。

## 二、目标用户

### 1. 个人模式

面向有少量投资经验的普通用户。默认使用人话、金额和关联原因表达：

- 今天哪些变化与我的持仓有关；
- 一项指标意味着什么；
- 组合可能承受多大金额损失；
- 我可以继续查看哪些信息。

### 2. 专家模式

面向金融从业者和有研究基础的用户。默认展示：

- 多维指标与来源；
- 四维研究评分；
- 多空分歧与置信度；
- 数据缺口、风险因素和可验证路径。

两个模式共享同一份事实和推理结果，只改变默认表达和信息密度。模式名称在界面、文档、对话中统一使用「个人 / 专家」，不再使用历史命名「个人投顾 / 专业投研」，避免与页面动作按钮冲突。

## 三、设计原则

### 1. AI 是主界面，不是附加聊天框

用户描述目标，系统决定需要查询行情、新闻、持仓、财务数据，还是启动多维研究。页面围绕 AI 的任务、结果和继续追问组织，不要求用户先学会传统股票终端。

### 2. 渐进披露

普通用户先看到结论和影响，专业指标可展开；专业用户先看到完整结构，但仍保留一句话结论。所有常用功能一次点击可达，全部功能最多两次点击可达。

### 3. 少而完整

一级导航控制在四项（持仓、风控、市场、新闻·研报）。没有明确核心场景的图表、指标和设置不进入主界面。

### 4. 极简界面，复杂能力可调出

默认界面保持极简，只显示用户此刻最需要的结论、影响和下一步动作。但复杂能力不能消失，而是通过渐进披露调出：

- 普通用户默认看到摘要、人话解释和少量关键证据；
- 专业用户可展开数据表、因子详情、来源、模型执行过程和历史研究；
- 高级执行选项进入「更多 / 专业展开 / 数据源详情 / 研究设置」，不占据首屏；
- 所有复杂功能必须从当前任务出发调出，不能以传统终端菜单矩阵呈现。

### 5. 事实、推理、建议边界清晰

- 事实来自数据源；
- 推理由规则和模型完成；
- 数据失败时明确降级；
- 不输出买卖、目标价和仓位指令；
- 不确定时说「不足以判断」。

### 6. 本地可信

单用户、SQLite、localhost、BYOK。持仓不上传到项目自有服务。模型配置可以保存在浏览器，也可以由用户明确选择写入本机 `.env`。

项目正常运行默认连接真实外网行情、新闻和模型服务。Mock 仅用于无 Key 演示和外部服务不可用时的明确降级，并在界面顶部通过 `BackendHealthBanner` 与数据源徽标显式提示，不能冒充真实数据。

## 四、核心产品结构

### 1. 单画布

StockResearch 只使用一个主画布。持仓、风控、市场、新闻研报不是四套独立页面，而是同一画布的四个稳定视角。

```text
┌──────────────────────────────────────────────────────────┐
│ 上证指数  沪深300  深证成指  创业板指   模式 / 数据 / 设置 │
├──────────────────────────────────────────────────────────┤
│ [持仓] [风控] [市场] [新闻·研报]              [AI 对话] │
├───────────────────────────────────────┬──────────────────┤
│                                       │                  │
│               单一主画布               │ 全局 AI 对话     │
│                                       │                  │
└───────────────────────────────────────┴──────────────────┘
```

顶部结构在所有视角中保持不变：

- 第一行是常驻大盘指数与全局设置；
- 第二行左侧是四个主视角；
- 第二行右侧只保留 AI 对话；
- 默认打开持仓。

### 2. 四个主视角

#### 持仓

- 组合市值、今日盈亏和累计盈亏；
- 持仓股票、成本、权重和行业集中度；
- 今日最重要的持仓变化；
- 点击股票后在画布内展开概览、走势、新闻和研报；
- 提供「分析这只股票」「解释今天盈亏」等 AI 动作。

#### 风控

- 人话风险结论和金额化损失；
- 风险贡献持仓与行业集中度；
- 压力情景与规则告警；
- VaR、回撤、Sharpe 等专业指标折叠；
- 提供「用人话解释」「谁贡献最大风险」等 AI 动作。

#### 市场

- AI 市场状态摘要；
- 指数走势、涨跌家数、成交与资金状态；
- 强弱行业和关键事件；
- 点击指数或行业后，可在画布中查看走势、新闻和研报；
- 不扩展为传统全市场扫描终端。

#### 新闻·研报

内部使用三个轻量标签：

- 与我相关；
- 市场要闻；
- AI 研报。

新闻是研究输入，研报是研究产出。新闻可转为研究，研报可继续追问。

### 3. 全局 AI 对话

AI 对话不是独立导航页，也不在每个视角重复实现一套聊天框。

- 所有工作区右侧都有同一个 AI 对话面板；
- 默认折叠，展开宽度约 380–440px；
- 支持横排（左右）与竖排（上下）布局切换，按钮在面板顶部；
- 展开时左侧当前页面继续显示并自适应压缩；
- **流式分析过程中展示思考轨迹；完成后自动收起，仅保留最终结论与结构化卡片**；
- Copilot 打开时顶栏按钮采用反色高亮，避免与背景同色不可读；
- 页面内只放「问 AI」类轻量动作；
- 复杂任务可从 AI 对话转入完整研究工作区。

典型页面动作：

| 页面    | 页面内容        | AI 对话快捷动作     |
| ----- | ----------- | ------------- |
| 持仓    | 股票、盈亏、集中度   | 解释今天的盈亏       |
| 风控    | 损失、风险贡献、告警  | 谁贡献了最大风险？     |
| 市场    | 指数、市场宽度、行业  | 今天市场为什么这样走？   |
| 新闻·研报 | 新闻、事件、AI 报告 | 解释这条新闻或继续追问研报 |

### 4. AI 对话上下文（用户 + 线程 + 可选附件）

产品保留三层信息的**语义**，但不做复杂的信息架构 polish。实现上简化为：

| 层级 | 范围 | 内容 |
|------|------|------|
| **用户上下文** | 全局 | 持仓、模式、语言、风险偏好、研究记忆 |
| **线程上下文** | 当前 session | 连续问答、研究对象、已生成报告 |
| **页面附件**（可选） | 单次提问 | 从画布「问 AI」带入的股票/新闻/组合；显示为可移除 chip，不单独做第三层 UX |

#### 用户上下文

在所有页面和线程共享：持仓、风险偏好与现金流、当前模式和语言、用户明确保存的偏好与研究记忆。

#### 线程上下文

只在当前任务线程内共享：连续问答、研究对象、已生成报告、用户确认的信息。切换页面不会自动清空线程。

#### 页面附件

用户从页面内「问 AI」动作进入时，才自动附加当前对象；AI 对话顶部显示标签，可一键移除。页面切换**不会**偷偷改变「它」「这只股票」等代词指向；不做「附加当前画布」引导类 polish（暂缓）。

### 5. 视角切换

- 保留当前线程；
- 不自动替换研究对象；
- 新视角可提示「附加当前画布」；
- 用户可继续原线程，也可基于当前画布新建线程；
- 深度研究默认创建独立线程；
- 新对话只清空线程，不清空持仓等长期上下文。

### 6. 复杂能力调用方式

参考近期中文/A 股开源项目的共同趋势，复杂能力不再作为一级导航暴露，而是通过当前画布和 AI 对话按需调出。

#### 6.1 今日简报，不做时间流

借鉴自动日报和盯盘项目的「每日决策看板」，但不恢复独立时间流。

- 持仓视角首屏保留「今日与你有关」卡片；
- 默认只展示 1–5 条最重要变化；
- 每条变化可展开完整证据，包括行情、新闻、风险、A 股特色因子；
- 用户可从卡片继续问 AI，自动附加对应股票/新闻/组合上下文；
- 历史简报进入研究记忆，不做独立信息流页面；
- 支持定时 cron 自动生成盘前（09:00）和收盘（15:30）简报，仅在 A 股交易日执行，用户可一键开启/关闭；
- 收盘后行情数据不再刷新，避免误导。

#### 6.2 轻量研究卡，不做多 Agent 剧场

借鉴多 Agent 项目的分析师分工，但不把 Agent 数量作为界面卖点。

个股或持仓深度分析默认输出一张轻量研究卡：

- 结论摘要；
- 基本面观点；
- 技术与市场结构观点；
- 新闻/政策/事件观点；
- 风险官观点；
- 数据缺口与下一步验证。

专业用户可展开完整执行过程、数据来源、因子检查状态和多空分歧。普通用户默认只看结论、影响和风险。

#### 6.3 专业信息展开（按模式分密度）

**不做**横跨四视角的统一 mega-drawer。复杂指标按模式决定默认可见性：

| 模式 | 首屏 | 折叠/展开 |
|------|------|-----------|
| **个人投顾** | 人话结论、金额影响 | 专业指标、VaR/Sharpe、因子明细、辩论过程 → 默认折叠，「专业展开」或 `<details>` |
| **专业投研** | 核心指标 inline（如 VaR、四维摘要） | 原始数据源、完整因子表、工具调用日志 → 二级折叠 |

各视角二级内容参考：

- 持仓：个股因子、行业暴露、研究记忆；
- 风控：VaR、回撤、相关性、压力情景；
- 市场：市场宽度、板块轮动、资金结构；
- 新闻·研报：来源可信度、影响路径、相关持仓；
- AI 对话：工具调用、数据源状态、研究参数（流式结束后折叠辩论等过程细节）。

轻量研究卡（§5.2）负责结论层；辩论与四维明细在 SSE `done` 之后默认折叠。

#### 6.4 数据源详情

每个 AI 结论旁边保留轻量来源提示，例如「行情：新浪，新闻：东财，财务：Tushare，可选」。用户点击后可看到：

- 数据源名称；
- 获取时间；
- 是否为实时、延迟、缓存或 Mock；
- 是否发生降级；
- 与其他来源是否冲突；
- 缺失数据对结论的影响。

## 五、核心场景

### 场景 A：首次体验

1. 用户选择个人或专家模式；
2. 系统加载示例持仓；
3. 首页直接展示今日关注；
4. 用户点击一条变化继续问 AI；
5. 用户看到结论、依据、风险和可继续问题。

目标：3 分钟内完成一次完整价值体验。

### 场景 B：询问个股

用户输入「帮我看看贵州茅台」：

- 系统识别标的，歧义时让用户确认；
- 自动选择直接分析或四维研究；
- 流式展示正在获取的事实和已完成维度；
- 结果先给结论，再给依据和不确定性；
- 可继续追问估值、技术状态、新闻影响或多空分歧。

### 场景 C：理解持仓风险

用户输入「我的组合风险怎么样」：

- 个人模式先显示金额化风险和主要来源；
- 专家模式先显示 VaR、回撤、波动率、Sharpe；
- 两者都允许展开另一层内容；
- 系统不提出交易指令。

### 场景 D：理解新闻

用户在持仓相关新闻上点击「AI 解释」：

- 为什么相关；
- 可能的影响路径；
- 哪些是事实；
- 哪些仍需验证；
- 关联到哪些持仓。

## 六、AI 原生交互

### 1. 一个输入框，多种任务

全局 AI 对话与研究工作区共享同一输入能力。用户无需选择 Agent，系统内部可使用：

- 直接 ReAct；
- 四维研究；
- 行业或市场研究；
- Plan-and-Execute；
- 风险规则与解释。

高级执行选项放入次级设置，不占据默认界面。

### 2. 过程可见，但不过度暴露

展示「正在识别股票」「正在读取行情」「技术面完成」等状态，不展示模型私有思维链，不用 Agent 数量制造复杂感。

### 3. 结果可继续

每份结果提供 2–4 个上下文追问，例如：

- 「哪些数据最可能推翻这个结论？」
- 「用专家模式展开估值和盈利质量。」
- 「这条新闻对我的其他持仓有影响吗？」

### 4. 主动发现

今日关注只在有真实变化时出现。宁可显示「没有明显变化」，也不生成噪声。

### 5. 术语弹窗（个人模式专属）

- 个人模式下，专业术语（PE、VaR、Sharpe 等）默认带可悬浮弹窗，给出一句人话解释；
- 专家模式下术语直出，不附加弹窗；
- 弹窗由独立的 `enable_glossary` 开关控制，可在设置中单独调整；
- 弹窗只出现在 AI 对话与研究卡中，不污染传统数据表。

### 6. A 股特色分析因子

StockResearch 的 A 股分析不能停留在通用股票研究模板。系统在分析持仓、个股、市场和新闻时，应把 A 股制度、资金结构和事件驱动作为显式检查项。

这些因子不是全部展示在首屏的指标墙，而是 AI 研究和风险解释的证据清单。普通用户看到「为什么相关」和「可能影响路径」，专业用户可展开数据来源、时间和缺口。

#### 6.1 制度与交易规则因子

- 涨跌停状态、连板、炸板、封单强弱；
- ST、退市风险警示、停复牌、临时停牌；
- T+1、最小交易单位、涨跌幅限制对流动性和退出的影响；
- 新股、次新股、注册制/核准制差异；
- 科创板、创业板、北交所等板块规则差异。

#### 6.2 资金与筹码因子

- 主力资金、北向资金、融资融券余额变化；
- 龙虎榜、游资席位、机构席位、大宗交易；
- 成交额、换手率、量比、异常放量/缩量；
- 股东户数、筹码集中度、机构持仓变化；
- ETF、行业主题资金流入流出。

#### 6.3 供给冲击与股权事件因子

- 限售股解禁规模与解禁市值占比；
- 大股东减持、增持、质押、被动减持风险；
- 定增、可转债、回购、分红、送转；
- 并购重组、资产注入、控制权变化；
- 业绩预告、业绩快报、问询函、监管函。

#### 6.4 政策、行业与主题因子

- 宏观政策、产业政策、监管口径变化；
- 会议、部委文件、地方政策、行业补贴；
- 主题热度与板块轮动，例如 AI、半导体、新能源、低空经济等；
- 同行业龙头、指数、ETF 与产业链上下游联动；
- 舆情热度与新闻来源可信度。

#### 6.5 财务与质量因子

- 估值：PE、PB、PS、PEG 与行业分位；
- 盈利质量：毛利率、净利率、ROE、现金流与应收账款；
- 成长：营收、利润、订单、产能和指引；
- 负债与偿债：资产负债率、短债、商誉、存货；
- 财报窗口和业绩兑现风险。

#### 6.6 技术与市场结构因子

- 趋势：均线、支撑阻力、突破/跌破；
- 波动：ATR、回撤、波动率；
- 强弱：相对行业、指数和同类标的的超额表现；
- 市场宽度：上涨家数、涨停/跌停家数、赚钱效应；
- 指数状态：上证指数、沪深300、深证成指、创业板指。

#### 6.7 风险解释规则

AI 输出不能直接给出买卖、目标价或仓位指令。A 股特色因子的使用方式是：

- 明确区分事实、推理和不确定性；
- 说明该因子影响的是流动性、情绪、基本面、估值还是事件预期；
- 数据缺失时标注「未验证」，不得让模型补造；
- 对普通用户给「人话影响」，对专业用户给「证据链和数据缺口」；
- 如果因子之间相互矛盾，应给出多空分歧，而不是强行单一结论。

### 7. 数据源策略

参考 `daily_stock_analysis`、`TradingAgents-astock`、`TradingAgents-CN`、`PanWatch` 等项目，StockResearch 的数据源策略从「单源可用」升级为「分层、多源、可解释、可降级」。

目标不是接入最多数据源，而是让用户知道：数据从哪里来、是否可信、是否新鲜、缺了什么。

#### 7.1 数据源分层

| 层级            | 目的          | 默认策略                               | 可选增强                        |
| ------------- | ----------- | ---------------------------------- | --------------------------- |
| L0 Mock       | 无网/无 Key 演示 | 内置示例数据                             | 明确标注 Mock，不冒充真实             |
| L1 免费默认源      | 开箱即用        | 新浪 / 东方财富 / 腾讯等公开源                 | provider 自动降级               |
| L2 Python 聚合库 | 补齐 A 股结构化数据 | AKShare、efinance、Baostock、mootdx 等 | 按功能懒加载                      |
| L3 用户 Key 源   | 更稳定、更丰富     | 用户自行配置                             | Tushare Pro、博查 AI 搜索、新闻 API |
| L4 本地缓存       | 稳定和复盘       | SQLite 缓存最近结果                      | 离线复盘、研究记忆                   |

#### 7.2 数据类型与推荐来源

| 数据类型     | 内置默认           | 增强来源                        | 用途             |
| -------- | ---------------- | --------------------------- | -------------- |
| 指数与实时行情  | 新浪 / 腾讯 / 东方财富   | AKShare / efinance / mootdx | 顶部指数、持仓刷新、市场状态 |
| K 线与技术指标 | 新浪 / 东方财富        | AKShare / mootdx            | 趋势、支撑阻力、波动     |
| 财务与估值    | 东方财富             | AKShare / Tushare Pro       | 财务质量、估值分位、业绩窗口 |
| 新闻与公告    | 东方财富 / 财联社公开源    | 博查 AI 联网搜索 / 巨潮信息网          | 新闻·研报、今日关注     |
| 研究报告     | 东方财富研报           | Tushare Pro                 | AI 研报、研究记忆     |
| 龙虎榜与资金   | 东方财富             | Tushare Pro                 | 游资、机构席位、资金异动   |
| 解禁、减持、质押 | 东方财富             | Tushare Pro / AKShare       | 供给冲击、股权风险      |
| 行业与主题    | 东方财富板块 / AKShare | Tushare Pro                 | 板块轮动、主题热度      |
| 研究记忆     | 本地 SQLite        | 用户导入文档                      | 历史观点、复盘和继续追问   |

#### 7.3 Provider 设计原则

- 每个 provider 必须返回 `source`、`fetched_at`、`latency_ms`、`is_cached`、`is_mock`、`degraded_reason`；
- 同类数据至少支持主备源，主源失败时自动降级；行情已实现「新浪 → AKShare → efinance」三层兜底；
- 高频公开源需要限流、随机抖动、Keep-Alive 和缓存，避免被封或拖慢界面；
- 数据 schema 以业务对象为中心，不把第三方字段直接暴露给前端；
- 后端保留原始响应摘要，便于 debug，但不把不稳定字段作为产品契约；
- 所有 live provider 用显式集成测试验证，默认单测不依赖外部服务。

#### 7.4 数据可信度与冲突处理

AI 输出中不只展示「来源」，还要展示可信度状态：

- **已验证**：多个来源一致，或来自用户配置的高可信源；
- **单源**：只有一个来源，允许使用但必须标注；
- **延迟**：数据不是实时，说明延迟窗口；
- **缓存**：使用本地缓存，说明缓存时间；
- **冲突**：多源结果不一致，列出冲突并降低置信度；
- **缺失**：数据不可得，不让模型补造。

#### 7.5 设置中的数据源体验

设置页只保留三个层级，不暴露复杂 provider 细节：

1. **默认真实数据**：无需 Key，使用免费公开源，适合首次体验；
2. **增强数据**：用户填入 Tushare Pro、博查 AI 搜索、新闻 API 等 Key；
3. **诊断面板**：专业用户查看 provider 状态、失败原因、缓存和限流。

普通用户只需要知道当前是「真实数据 / 缓存 / Mock / 降级」。专业用户可以展开完整来源。

## 八、Agent 与输出契约

统一输出包含：

- `reply`：当前模式下的一句话结论与解释；
- `cards`：事实、研究、风险和计划等结构化卡片；
- `intent`：实际任务；
- `partial`：是否发生超时或降级；
- `llm_usage`：模型用量；
- 数据来源和时间状态。

失败处理：

- 股票歧义不猜测；
- 数据源失败则切换备用源并提示；
- 单 Agent 超时返回部分结果；
- 模型未配置时引导设置或 Mock；
- 数据不足时列出缺失项；
- SSE 中断保留断点。

## 九、技术架构

```text
React UI
  ├─ 单画布：持仓 / 风控 / 市场 / 新闻·研报
  ├─ 全局 AI 对话（横排 / 竖排可切换，宽度可调）
  │    ├─ 长期用户上下文
  │    ├─ 线程上下文
  │    └─ 显式页面上下文
  ├─ 后端健康监控横幅
  └─ 模式只控制呈现与默认信息密度
          │ REST / SSE
FastAPI 协议层
          │
统一任务执行内核
  ├─ 路由与工具选择
  ├─ ReAct / Plan-Execute
  ├─ 个股 / 行业 / 市场研究
  ├─ 风险与中立性边界
  └─ 简报定时任务（APScheduler，仅 A 股交易日）
          │
统一结果处理
  ├─ 中立性与合规
  ├─ 术语和阅读模式
  ├─ partial / disclaimer
  └─ 会话持久化
          │
Provider + SQLite
```

工程要求：

- 普通响应与 SSE 不复制业务路由；
- SSE 只负责增加进度事件；
- 最终输出处理只有一个入口；
- 前端按领域拆分 API、状态和卡片；
- AI 对话状态与页面状态解耦；
- 页面通过统一接口提供可见、可移除的临时上下文；
- 数据库 schema 变更可追踪；
- CI 运行测试、构建和静态检查；
- 真实外网 Provider 使用显式 live integration test 验证，稳定单测不依赖第三方服务在线状态。

## 十、验收标准

- 首次体验 3 分钟内完成；
- 常用功能一次点击可达，全部功能两次点击可达；
- 四个主视角均可打开同一个 AI 对话；
- 视角切换保留线程，不隐式替换研究对象；
- 页面上下文标签可见并可移除；
- 指数栏与顶部按钮在视角切换时保持稳定；
- 个人模式首屏主要信息块不超过 5 个；
- 同一请求通过普通和流式接口得到一致的最终处理；
- 每次流式请求只发送一个最终 `done`；
- Mock 下核心演示完整；
- 数据失败和超时有明确降级，并在顶部横幅提示；
- AI 结论可查看数据来源、时间、缓存、Mock、降级与冲突状态；
- A 股因子检查可展开查看每个因子的 provider、层级、验证状态和缺失来源；
- 收盘后行情数据不再刷新；
- `pytest`、前端测试、前端生产构建通过；
- 项目不增加非目标功能。

## 十三、未来开发方向

本节列出已识别但尚未实现的产品演进方向，作为后续规划的单一来源。每项标注所属视角、目标与待解决问题，不承诺排期。

### 下一步开发（V9.0 优先）

以下三项为近期优先方向：

#### 1. 自选股

- 独立于持仓的观察列表，支持添加、移除、排序与备注；
- 自选股纳入今日关注扫描、新闻关联与 AI 对话上下文（可与持仓一并引用）；
- 市场/新闻视角可按「仅自选股」「持仓+自选股」过滤；
- 数据模型与 API 需与持仓解耦，UI 在持仓视角或独立入口展示。

#### 2. 涨跌提醒

- 定时任务（复用 APScheduler）监测**持仓**与**自选股**实时/延迟行情；
- 用户可为单只股票或全局设定涨跌幅阈值（如 ±3%、±5%）；
- 触发条件：相对昨收或相对用户设定基准的涨跌幅超过阈值；
- 提醒通道：应用内通知（首版）；可选扩展邮件、桌面通知（需用户显式配置）；
- 同一标的同一交易日去重，避免重复轰炸；提醒内容带 disclaimer 与数据时间戳，不含买卖指令。

#### 3. 行业板块涨跌显示

- 在市场视角展示行业/概念板块涨跌幅排行（领涨、领跌、成交额前列）；
- 支持按日涨跌幅、5 日/20 日强弱等维度切换（首版至少日涨跌幅）；
- 与现有「强弱行业」摘要联动，可点击板块查看成分股与相关新闻；
- 数据来源优先东方财富板块 / AKShare，遵循 §六.7 分层与降级规则。

### 后续方向

#### 4. 技术面：K 线图与 AI 辅助分析

- 在个股技术面视角显示标准 K 线图，覆盖日线/周线，支持 MA、BOLL、MACD、RSI、KDJ 等常见辅助指标；
- 提供「AI K 线解读」动作，由 LLM 结合形态、量价、指标给出一段结构化解读，标注置信度与数据缺口；
- 探索「AI 自动化辅助线深度分析」，由模型识别关键支撑/阻力、趋势线、缺口并叠加在图上，结果可展开查看识别依据；
- 不替代人工判断，所有 AI 标注必须可关闭、可溯源到具体数据点。

### 5. 基本面：同行业对比

- 在个股基本面视角新增「同行业对比」模块，默认展示同行业 3–5 家可比公司；
- 对比维度至少包含估值（PE/PB/PS）、盈利质量（毛利率/净利率/ROE）、成长（营收/利润增速）和负债（资产负债率）；
- 数据来源优先复用 AKShare / 东方财富 / Tushare Pro，冲突时按 §六.7.4 规则标注；
- 个人模式给出人话结论（如「估值高于同行」），专家模式给出完整数据表与分位。

### 6. 今日关注：一句话点评

- 今日关注卡片由「链接到风控检查」改为「一句话点评」，直接在卡片内给出与持仓相关的简短结论；
- 点评基于行情变化、新闻影响、A 股特色因子综合生成，遵守中立边界，不输出买卖指令；
- 用户仍可从卡片手动进入深度研究或风控视角，但不再强制跳转；
- 历史点评进入研究记忆，便于复盘。

### 7. 时间流：实时重大新闻通报与盘后分发

- 虽不恢复独立时间流页面，但保留并增强定时任务能力：
  - 盘中 cron 实时扫描重大新闻，命中持仓/关注时通过现有今日关注卡片呈现，不做独立信息流；
  - 盘后（如 15:30）自动生成本日简报，通过邮件或 AI 对话机器人推送给用户；
- 探索接入 MCP（Model Context Protocol）类接口实现自动分发，候选方案包括 Open Claw、Hermes Agent 等，需评估稳定性、合规性与本地部署成本；
- 邮件通道需用户显式配置 SMTP；AI 对话机器人通道需用户显式授权；
- 推送内容必须带 disclaimer 与数据时间戳，不得包含买卖指令。

## 十五、工程附录

> 本节吸收原 `docs/DEVELOPMENT_PLAN.md`（V1.0，2026-05-27）中仍适用的工程参考。**已剔除**与 PRD 非目标冲突的内容：JWT/注册登录、PostgreSQL/Redis/Celery、公网 SaaS、付费/社区/多端、留存漏斗等 SaaS 指标。

### 15.1 核心闭环与行业对标

```text
数据采集 → 多 Agent 分析 → 风控兜底 → 对话呈现
```

| 维度 | 行业常见做法 | StockResearch 策略 |
|------|-------------|-------------------|
| 投研输出 | 单 Agent 直接给结论 | 四维并行 → 可选多空辩论 + 裁判 |
| 角色设计 | 通用金融 Agent | A 股原生四维（基本面/技术面/情绪面/筹码面） |
| 风控 | VaR 等专业指标 | 规则引擎 + 人话翻译 |
| 合规 | 事后审核 | 输出端中立性过滤 + 不做买卖建议 |
| 成本 | 全量大模型 | 模型分级 + 缓存 + Mock 降级 |

**感知-大脑-行动分层**（FinRobot 参考）：

```text
行动层：React 单画布 + 卡片 UI + 今日关注
大脑层：LangGraph Orchestrator + 四维 Agent + 辩论/裁判
感知层：新浪/东财/AKShare + 可选 Tushare + SQLite 缓存
```

### 15.2 Agent 设计原则

1. **视角隔离**：基本面/技术面/情绪面/筹码面工具集隔离，禁止跨域污染。
2. **Research 先于 Battle**：四维并行完成后再进入辩论。
3. **Draft 哲学**：输出带置信度、来源、免责声明；永不输出买卖/目标价/仓位指令。
4. **混合编排**：意图路由、风控阈值、情感规则用代码；LLM 负责推理与语言化。
5. **Push > Chat**（远期）：主动推送、WebSocket 订阅等可作为涨跌提醒的扩展通道；当前以今日关注卡片与定时简报代替。

**投研子 Agent 工具集隔离（参考）**：

| 子 Agent | 允许调用的 Tool |
|---------|----------------|
| fundamental | 财务、估值、行业 peers |
| technical | K 线、均线、技术指标 |
| sentiment | 新闻情感、舆情 |
| chips | 龙虎榜、资金流、股东户数 |

**辩论机制（已实现，默认可关）**：

```text
Round 0: 四维并行 → 结构化结论 + confidence
Round 1–N: Bull ↔ Bear（可配置轮数）
Output: 共识结论 + 核心分歧 + 裁判 summary（流式可见，done 后折叠）
```

### 15.6 风险矩阵

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| AI 幻觉致误导 | 中 | 极高 | 来源标注 + 因子 missing + 不做买卖建议 |
| 数据源断供 | 高 | 中 | 主备降级 + partial |
| LLM 成本失控 | 中 | 高 | 缓存 + Mock + 辩论可关 |
| 用户不录入持仓 | 高 | 高 | Onboarding + 示例持仓 |
| 辩论延迟过长 | 中 | 中 | 流式中间结果 + done 后折叠 |
| 政策合规 | 中 | 高 | 不碰交易执行 + 免责声明 |

### 15.7 数据库迁移方案

**现状**：SQLite + `schema_migrations` 表 + 手写 versioned migration（`db/session.py`）。

**短期（推荐）**：延续手写 migration；每次 schema 变更增加 `_migration_00N_*` + `test_db_session` 覆盖。

**中期（可选）**：当 migration > 5 条或需 column rename 时，引入 Alembic：

1. `alembic init`，baseline 对应当前 models；
2. 现有 DB stamp 至当前 version；
3. CI 增加 `alembic upgrade head` + pytest。

**非目标**：PostgreSQL、多租户 schema、在线 migration 零 downtime。
