# StockResearch 产品需求文档

**版本：V8.0 · 本地 AI 原生 MVP**

## 一、产品定位

StockResearch 是一个本地联网运行的个人 AI 投顾与 AI 投研 MVP。

它不准备上线成为服务，不连接券商，不替用户交易。项目的核心价值是展示：如何把持仓、行情、新闻、风险和多 Agent 研究组织成一款真正 AI 原生、普通人易用、专业人士也有研究深度的产品。

一句话定义：

> 用 AI 帮用户理解“今天发生了什么、为什么与我有关、还需要验证什么”。

## 二、目标用户

### 1. 个人投顾模式

面向有少量投资经验的普通用户。默认使用人话、金额和关联原因表达：

- 今天哪些变化与我的持仓有关；
- 一项指标意味着什么；
- 组合可能承受多大金额损失；
- 我可以继续查看哪些信息。

### 2. 专业投研模式

面向金融从业者和有研究基础的用户。默认展示：

- 多维指标与来源；
- 四维研究评分；
- 多空分歧与置信度；
- 数据缺口、风险因素和可验证路径。

两个模式共享同一份事实和推理结果，只改变默认表达和信息密度。

## 三、设计原则

### 1. AI 是主界面，不是附加聊天框

用户描述目标，系统决定需要查询行情、新闻、持仓、财务数据，还是启动多维研究。页面围绕 AI 的任务、结果和继续追问组织，不要求用户先学会传统股票终端。

### 2. 渐进披露

普通用户先看到结论和影响，专业指标可展开；专业用户先看到完整结构，但仍保留一句话结论。所有常用功能一次点击可达，全部功能最多两次点击可达。

### 3. 少而完整

一级导航控制在五项。没有明确核心场景的图表、指标和设置不进入 MVP。

### 4. 事实、推理、建议边界清晰

- 事实来自数据源；
- 推理由规则和模型完成；
- 数据失败时明确降级；
- 不输出买卖、目标价和仓位指令；
- 不确定时说“不足以判断”。

### 5. 本地可信

单用户、SQLite、localhost、BYOK。持仓不上传到项目自有服务。模型配置可以保存在浏览器，也可以由用户明确选择写入本机 `.env`。

项目正常运行默认连接真实外网行情、新闻和模型服务。Mock 只用于首次演示、无 Key 体验和外部服务不可用时的明确降级，不能冒充真实数据。

## 四、核心产品结构

### 1. 单画布

StockResearch 只使用一个主画布。持仓、风控、市场、新闻研报不是四套独立页面，而是同一画布的四个稳定视角。

```text
┌──────────────────────────────────────────────────────────┐
│ 上证指数  沪深300  深证成指  创业板指   模式 / 数据 / 设置 │
├──────────────────────────────────────────────────────────┤
│ [持仓] [风控] [市场] [新闻·研报]              [Copilot] │
├───────────────────────────────────────┬──────────────────┤
│                                       │                  │
│               单一主画布               │ 全局 Copilot     │
│                                       │                  │
└───────────────────────────────────────┴──────────────────┘
```

顶部结构在所有视角中保持不变：

- 第一行是常驻大盘指数与全局设置；
- 第二行左侧是四个主视角；
- 第二行右侧只保留 Copilot；
- 默认打开持仓。

### 2. 四个主视角

#### 持仓

- 组合市值、今日盈亏和累计盈亏；
- 持仓股票、成本、权重和行业集中度；
- 今日最重要的持仓变化；
- 点击股票后在画布内展开概览、走势、新闻和研报；
- 提供“分析这只股票”“解释今天盈亏”等 AI 动作。

#### 风控

- 人话风险结论和金额化损失；
- 风险贡献持仓与行业集中度；
- 压力情景与规则告警；
- VaR、回撤、Sharpe 等专业指标折叠；
- 提供“用人话解释”“谁贡献最大风险”等 AI 动作。

#### 市场

- AI 市场状态摘要；
- 指数走势、涨跌家数、成交与资金状态；
- 强弱行业和关键事件；
- 点击指数或行业后，可在画布中查看走势、新闻和研报；
- 不扩展为传统全市场扫描终端。

#### 新闻·研报

内部使用三个轻量标签：

- 与我相关；
- 市场要闻；
- AI 研报。

新闻是研究输入，研报是研究产出。新闻可转为研究，研报可继续追问。

### 2. 全局 Copilot

Copilot 不是独立导航页，也不在每个视角重复实现一套聊天框。

- 所有工作区右侧都有同一个 Copilot；
- 默认折叠，展开宽度约 380–440px；
- 展开时左侧当前页面继续显示并自适应压缩；
- 页面内只放“问 AI”类轻量动作；
- 复杂任务可从 Copilot 转入完整研究工作区。

典型页面动作：

| 页面 | 页面内容 | Copilot 快捷动作 |
|---|---|---|
| 持仓 | 股票、盈亏、集中度 | 解释今天的盈亏 |
| 风控 | 损失、风险贡献、告警 | 谁贡献了最大风险？ |
| 市场 | 指数、市场宽度、行业 | 今天市场为什么这样走？ |
| 新闻·研报 | 新闻、事件、AI 报告 | 解释这条新闻或继续追问研报 |

### 3. Copilot 三层上下文

#### 长期用户上下文

在所有页面和线程共享：

- 持仓；
- 风险偏好与现金流；
- 当前模式和语言；
- 用户明确保存的偏好与研究记忆。

#### 线程上下文

只在当前任务线程内共享：

- 连续问答；
- 研究对象；
- 已生成报告；
- 用户确认的信息。

切换页面不会自动清空线程。

#### 页面上下文

临时且显式附加：

- 当前股票；
- 当前新闻；
- 当前组合；
- 当前报告。

页面上下文必须在 Copilot 顶部显示标签，可一键移除。页面切换不能偷偷改变当前研究对象或代词指向。用户从页面内“问 AI”动作进入时，才自动附加该页面上下文。

### 4. 视角切换

- 保留当前线程；
- 不自动替换研究对象；
- 新视角可提示“附加当前画布”；
- 用户可继续原线程，也可基于当前画布新建线程；
- 深度研究默认创建独立线程；
- 新对话只清空线程，不清空持仓等长期上下文。

## 五、核心场景

### 场景 A：首次体验

1. 用户选择个人投顾或专业投研；
2. 系统加载示例持仓和 Mock 数据；
3. 首页直接展示今日关注；
4. 用户点击一条变化继续问 AI；
5. 用户看到结论、依据、风险和可继续问题。

目标：3 分钟内完成一次完整价值体验。

### 场景 B：询问个股

用户输入“帮我看看贵州茅台”：

- 系统识别标的，歧义时让用户确认；
- 自动选择直接分析或四维研究；
- 流式展示正在获取的事实和已完成维度；
- 结果先给结论，再给依据和不确定性；
- 可继续追问估值、技术状态、新闻影响或多空分歧。

### 场景 C：理解持仓风险

用户输入“我的组合风险怎么样”：

- 个人投顾模式先显示金额化风险和主要来源；
- 专业投研模式先显示 VaR、回撤、波动率、Sharpe；
- 两者都允许展开另一层内容；
- 系统不提出交易指令。

### 场景 D：理解新闻

用户在持仓相关新闻上点击“AI 解释”：

- 为什么相关；
- 可能的影响路径；
- 哪些是事实；
- 哪些仍需验证；
- 关联到哪些持仓。

## 六、AI 原生交互

### 1. 一个输入框，多种任务

全局 Copilot 与研究工作区共享同一输入能力。用户无需选择 Agent，系统内部可使用：

- 直接 ReAct；
- 四维研究；
- 行业或市场研究；
- Plan-and-Execute；
- 风险规则与解释。

高级执行选项放入次级设置，不占据默认界面。

### 2. 过程可见，但不过度暴露

展示“正在识别股票”“正在读取行情”“技术面完成”等状态，不展示模型私有思维链，不用 Agent 数量制造复杂感。

### 3. 结果可继续

每份结果提供 2–4 个上下文追问，例如：

- “哪些数据最可能推翻这个结论？”
- “用专业模式展开估值和盈利质量。”
- “这条新闻对我的其他持仓有影响吗？”

### 4. 主动发现

今日关注只在有真实变化时出现。宁可显示“没有明显变化”，也不生成噪声。

## 七、功能范围

### 必须有

- 双模式、Onboarding、示例持仓；
- 今日关注；
- AI 对话和 SSE；
- 个股、行业和市场研究；
- 四维研究和可选辩论；
- 持仓、相关新闻、组合风险；
- 数据来源与降级提示；
- 本地模型和数据源设置；
- 中英文。

### 统一简化

- 技术面只保留 K 线、均线、支撑阻力和必要指标；
- 财务面只保留估值、盈利质量、成长和负债核心指标；
- 首页不展示全市场大而全仪表盘；
- 设置不展示普通用户无需理解的内部参数；
- 多空辩论默认折叠，结论优先。

### 明确不做

- 公网部署、账号、多用户、收费；
- 券商连接、交易执行、自动调仓；
- Level-2、盘口、全市场扫描器；
- 复杂指标库和传统终端功能矩阵；
- 社区、跟单和排行榜；
- 移动端优先、PWA；
- 复杂动画、3D 图表和装饰性可视化；
- 独立时间流、收件箱和任务管理视图；
- 港股、美股等多市场扩张。

## 八、Agent 与输出契约

统一输出包含：

- `reply`：当前模式下的一句话结论与解释；
- `cards`：事实、研究、风险和计划等结构化卡片；
- `intent`：实际任务；
- `partial`：是否发生超时或降级；
- `llm_usage`：模型用量；
- 数据来源和时间状态。

失败处理：

- 股票歧义不猜测；
- 数据源失败则切换备用源并提示；
- 单 Agent 超时返回部分结果；
- 模型未配置时引导设置或 Mock；
- 数据不足时列出缺失项；
- SSE 中断保留断点。

## 九、技术架构

```text
React UI
  ├─ 单画布：持仓 / 风控 / 市场 / 新闻·研报
  ├─ 全局 Copilot
  │    ├─ 长期用户上下文
  │    ├─ 线程上下文
  │    └─ 显式页面上下文
  └─ 模式只控制呈现与默认信息密度
          │ REST / SSE
FastAPI 协议层
          │
统一任务执行内核
  ├─ 路由与工具选择
  ├─ ReAct / Plan-Execute
  ├─ 个股 / 行业 / 市场研究
  └─ 风险
          │
统一结果处理
  ├─ 中立性与合规
  ├─ 术语和阅读模式
  ├─ partial / disclaimer
  └─ 会话持久化
          │
Provider + SQLite
```

工程要求：

- 普通响应与 SSE 不复制业务路由；
- SSE 只负责增加进度事件；
- 最终输出处理只有一个入口；
- 前端按领域拆分 API、状态和卡片；
- Copilot 状态与页面状态解耦；
- 页面通过统一接口提供可见、可移除的临时上下文；
- 数据库 schema 变更可追踪；
- CI 运行测试、构建和静态检查。
- 真实外网 Provider 使用显式 live integration test 验证，稳定单测不依赖第三方服务在线状态。

## 十、验收标准

- 首次体验 3 分钟内完成；
- 常用功能一次点击可达，全部功能两次点击可达；
- 四个主视角均可打开同一个 Copilot；
- 视角切换保留线程，不隐式替换研究对象；
- 页面上下文标签可见并可移除；
- 指数栏与五个顶部按钮在视角切换时保持稳定；
- 个人投顾首屏主要信息块不超过 5 个；
- 同一请求通过普通和流式接口得到一致的最终处理；
- 每次流式请求只发送一个最终 `done`；
- Mock 下核心演示完整；
- 数据失败和超时有明确降级；
- `pytest`、前端测试、前端生产构建通过；
- 项目不增加非目标功能。

## 十一、实施优先级

### P0：架构可信

1. 统一普通与流式结果处理；
2. 消除重复 `done`；
3. 建立两条路径的一致性测试；
4. 修复会影响运行正确性的类型问题。

### P1：产品收束

1. 建立顶部视角栏与单一主画布；
2. 全局 Copilot 与三层上下文；
3. 画布内轻量 AI 动作；
4. 结果增加继续追问；
5. 简化设置和专业指标默认展示。

### P2：工程可持续

1. 拆分巨型前端模块；
2. 建立数据库迁移；
3. 静态检查进入 CI；
4. 校准文档、截图和真实状态。
