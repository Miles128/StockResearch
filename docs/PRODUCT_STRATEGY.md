# 产品战略方案

基于 StockResearch PRD V6.0，对两个核心战略问题的深度分析与落地方案。

1. 专业术语大众化的实现路径——开关模式：术语弹窗 vs 友善模式
2. 中立型智能投顾的架构设计——产品不商业化，专注中立投顾

---

## 问题一：专业术语大众化——开关模式

### 设计理念：两种阅读模式，用户自选

不做"一个输出同时服务两类人"的妥协，而是给用户**明确的模式切换**：

| 模式 | 目标用户 | 核心规则 | 术语处理 |
|------|----------|----------|----------|
| **专业模式** | 有投资基础的用户 | 术语直接出现，数据完整 | 可点击弹窗查看定义+上下文数值 |
| **友善模式** | 新手/普通投资者 | 人话优先，术语用类比替代 | 无弹窗，LLM 直接输出通俗解释 |

### 模式差异示例

```
【专业模式】
"招商银行 PE 35.2，高于行业均值 42%，ROE 16.8%。
 逼近止损关注线（距 8% 阈值仅 1.2%）。"

→ PE、ROE、止损关注线 均显示为可点击的淡色下划线
→ 点击弹出：PE = 市盈率，当前 35.2，行业均值 24.8，估值偏高

【友善模式】
"招商银行现在股价偏贵——买它花的钱是它年利润的 35 倍，
 行业平均才 25 倍。不过它赚钱能力还不错。
 离你设定的关注线很近了，只差 1.2%。"

→ 无术语标记，无弹窗，纯自然语言
```

### 架构设计

#### 1. 模式状态管理

```
用户设置（前端 SettingsPanel）
    │
    ├── reading_mode: "professional" | "friendly"  (默认 friendly)
    │
    ▼
API 请求携带 reading_mode 参数
    │
    ▼
output_style_scope(reading_mode=...)  设置 ContextVar
    │
    ├── friendly  → Prompt 注入友善写作规则 + 跳过词库标记
    └── professional → Prompt 注入专业写作规则 + 输出经词库标记
```

#### 2. Prompt 层改动

**友善模式 Prompt 规则**（注入 system prompt）：

```
【友善写作规则】
1. 用日常语言，避免金融术语。必须用术语时，用括号给出通俗类比
2. 数字必须带"意味着什么"的解释，不能只列数字
3. 把指标翻译成钱的感受：不说"VaR 4.32%"，说"95% 概率一天亏不超过 ¥2,300"
4. 类比优先：PE = "花多少钱买1元年利润"，ROE = "每100元本金能赚多少"

示例：
  ❌ "ROE 32.1%，毛利率 52.3%"
  ✅ "赚钱能力很强——每100元本金一年能赚32元，行业平均才18元。
      每100元收入能留下52元利润。"
```

**专业模式 Prompt 规则**：

```
【专业写作规则】
1. 术语直接使用，数据完整呈现
2. 关键指标首次出现时附行业标准对比
3. 保持投研报告的专业口径，客观克制
4. 术语会自动标记为可点击，无需在文中额外解释

示例：
  ✅ "ROE 32.1%（行业均值 18.2%），毛利率 52.3%"
  ✅ "VaR 95% = 4.32%，CVaR = 6.15%"
```

#### 3. 静态术语词库（仅专业模式使用）

**设计原则**：

- 只覆盖系统高频输出的术语（约 80-120 个）
- 每个词条 = 名称 + 英文 + 一句话定义 + 类比（友善模式用）+ 上下文模板

**词库结构**（`glossary.json`）：

```json
{
  "PE": {
    "en": "Price-to-Earnings Ratio",
    "short": "市盈率",
    "def": "股价 ÷ 每股收益，衡量估值高低",
    "analogy": "花多少钱买1元年利润",
    "context_template": "当前 {stock} PE 为 {value}，行业均值 {industry_avg}，{assessment}"
  },
  "ROE": {
    "en": "Return on Equity",
    "short": "净资产收益率",
    "def": "净利润 ÷ 净资产，衡量赚钱效率",
    "analogy": "每100元本金一年能赚多少",
    "context_template": "当前 {stock} ROE 为 {value}%，行业均值 {industry_avg}%"
  },
  "VaR": {
    "en": "Value at Risk",
    "short": "风险价值",
    "def": "在给定置信度下的最大可能亏损",
    "analogy": "95%概率不会亏超过这个数",
    "context_template": "未来一天，95%概率亏损不超过 ¥{amount}（VaR {pct}%）"
  }
}
```

**匹配策略**（仅专业模式激活）：

- 后端：LLM 输出文本经 `glossary_marker` 处理，匹配到的术语包裹为 `<term data-id="PE">PE</term>`
- 前端：渲染时将 `<term>` 转为可点击的淡色下划线文本
- 不做 NLP 分词，用正则+词边界匹配

#### 4. 前端术语弹窗（仅专业模式）

**交互设计**：

- 术语显示为淡色下划线 + 点击弹出浮层
- 弹窗内容：中文名 + 英文名 + 一句话定义 + 当前上下文数值
- 弹窗样式轻量，不打断阅读流
- 底部可选："了解更多 →" 链接到内置术语详情页

**友善模式下的表现**：无任何术语标记，无下划线，无弹窗。纯文本阅读体验。

#### 5. LLM 标记指令（仅专业模式兜底）

- 专业模式下，system prompt 追加："输出中涉及金融术语时，首次出现用「术语」标记"
- 后端解析标记，与静态词库交叉验证
- 静态词库未覆盖的术语：标记后显示下划线，弹窗中标注"AI 生成解释"
- 长期目标：将高频新术语逐步纳入静态词库

## 问题二：中立型智能投顾架构

### 产品定位

**开源、免费、中立的投资认知工具。** 不商业化，不卖钱，不走向建议型投顾。

```
我们要做的：帮用户看见、理解、预演 → 认知增强
我们不做：帮用户决策、建议买卖 → 永远不做
```

### 现状：当前合规边界

| 机制 | 内容 |
|------|------|
| 硬禁止 | 禁止输出买入/卖出/目标价/建仓比例 |
| 软约束 | "帮用户理解不是帮用户决策"、"阈值归用户所有" |
| 免责声明 | 三层机制（prompt→剥离→UI统一展示） |
| 新闻过滤 | 三级关键词过滤（黑名单/重降权/轻降权） |

### 转型路线：两个阶段（只做中立型）

#### 阶段一：认知增强型投顾（当前可做，0合规风险）

**核心能力：帮用户看见 + 帮用户理解**

| 功能 | 描述 | 中立性保障 |
|------|------|------------|
| 持仓风险透视 | "你的组合 70% 集中在金融板块，历史波动比分散持仓高 40%" | 只陈述事实，不建议调仓 |
| 事件影响推演 | "降准对银行持仓的影响路径：净息差→利润→股价，历史上类似事件平均影响+2.3%" | 历史统计，不是预测 |
| 持仓健康度评分 | 分散度/质量/波动三维评分 | 评分标准透明可调，用户可修改阈值 |
| 关键位置提醒 | "距你的止损关注线还剩 1.8%" | 用户自己设的线，系统只监测 |
| 交叉验证 | "3 个维度都指向同一方向（技术面弱势+基本面恶化+资金流出）" | 信息聚合，不是建议 |

**合规原则**：所有功能都是"如果...那么..."的条件逻辑，不出现"应该..."的指令语气。

#### 阶段二：场景推演型投顾（低合规风险）

**核心能力：帮用户预演**

| 功能 | 描述 | 中立性保障 |
|------|------|------------|
| What-If 分析 | "如果银行板块再跌 10%，你的组合整体亏损约 ¥4,500" | 纯数学计算，不预测会不会跌 |
| 压力测试 | "2015 年股灾级别下，你的组合最大回撤约 35%" | 历史情景回放，不是预测 |
| 再平衡对比 | "当前组合 vs 等权组合 vs 最小方差组合，过去一年表现对比" | 并列展示，不推荐某个 |
| 决策清单 | "今天需要你关注的事项：① 贵州茅台触及止损关注线 ② 白酒消费数据发布" | 清单不是建议，是提醒 |
| 纪律检查 | "你的止损线是 8%，但过去 3 次触及时都没有卖出" | 反映用户自身纪律，不是系统建议 |
| 情绪标记 | "连续 3 天频繁查看同一持仓，可能处于焦虑状态" | 行为金融学观察，不是交易建议 |
| 计划跟踪 | "你上周说要等 PE 回到 25 再加仓，当前 PE 24.8" | 追踪用户自己的计划 |

**合规原则**：所有功能都是"假设性场景"，明确标注"以下为历史数据推演，不代表未来走势"。

**不做**：阶段三（投资框架型）和阶段四（智能匹配型）——这两类涉及建议和推荐，商业化产品才需要。开源免费工具专注于认知增强。

### 保持中立风格的架构设计

```
┌─────────────────────────────────────────────────┐
│                  中立性守卫层                      │
│                                                   │
│  ┌───────────┐  ┌───────────┐  ┌───────────┐    │
│  │ 禁令过滤器 │  │ 语气校准器 │  │ 归因引擎  │    │
│  │           │  │           │  │           │    │
│  │ 买入→关注  │  │ 建议→观察  │  │ 系统发现→  │    │
│  │ 卖出→评估  │  │ 应该→可能  │  │ 你的数据表明│    │
│  │ 目标价→   │  │ 推荐→参考  │  │           │    │
│  │ 合理区间   │  │ 紧急→留意  │  │           │    │
│  └───────────┘  └───────────┘  └───────────┘    │
│                                                   │
│  ┌───────────────────────────────────────────┐   │
│  │           平衡性检查器                      │   │
│  │ 负面信号必配正面/中性信息                     │   │
│  │ 单一观点必附反对/替代视角                    │   │
│  │ 预测性陈述必附置信度+不确定声明              │   │
│  └───────────────────────────────────────────┘   │
└─────────────────────────────────────────────────┘
```

#### 1. 禁令过滤器（扩展现有机制）

在 `constants.py` 的 `NEWS_BLACKLIST_KEYWORDS` 基础上，增加 **输出禁令词表**：

```python
OUTPUT_BANNED_PATTERNS = [
    (r"建议(买入|卖出|加仓|减仓)", "建议关注/评估"),
    (r"目标价\s*[\d.]+", "合理估值区间"),
    (r"应该\s*(买|卖|持有)", "可能值得留意"),
    (r"(强烈|坚决)\s*(推荐|建议)", "值得关注"),
    (r"赶紧|立即|马上|务必", None),  # 直接删除紧迫性词汇
]
```

后处理层用正则替换，不依赖 LLM 遵守。

#### 2. 语气校准器

在 `output_style.py` 中增加语气规则，注入到所有 agent prompt：

```
【语气规则】
- 用"值得关注"替代"建议买入"
- 用"可能"替代"将会"
- 用"你的数据显示"替代"系统建议"
- 用"历史统计表明"替代"预计"
- 任何预测性陈述后必须附"不保证未来走势"
```

#### 3. 归因引擎

所有"建议性"输出必须归因到用户自身数据：

```
❌ "建议关注银行板块" → 系统在推荐
✅ "你持仓中银行板块占比 70%，近期有降准利好" → 基于你的持仓事实

❌ "应该适当分散" → 系统在指挥
✅ "当前集中度评分 3/10，低于 5 分代表较集中" → 基于你的数据指标
```

#### 4. 平衡性检查器

在 orchestrator 的最终输出前，增加一步平衡性检查：

- 统计输出中正面/负面/中性信号的占比
- 如果负面信号 > 60%，自动补充"同时注意到..."的平衡信息
- 如果只有单一维度观点，自动标注"以上仅为{维度}视角，其他维度可能有不同结论"

### 术语词库 vs 外部链接的最终建议

| 方案 | 采用程度 | 理由 |
|------|----------|------|
| 内嵌弹窗（定义+当前上下文） | **主路径**（专业模式） | PRD §6.5 核心价值，不打断体验 |
| 内置术语详情页 | **补充**（专业模式） | 需要深入了解时的进阶路径 |
| 外部百科链接 | **可选** | 仅在详情页底部作为"了解更多"的出口 |
| LLM 实时生成解释 | **兜底**（专业模式） | 静态词库未覆盖的术语，标注"AI 生成" |
| 友善模式类比 | **主路径**（友善模式） | LLM 直接输出通俗类比，无需弹窗 |

**不建议**将外部链接作为主路径——跳出应用会打断投资决策流程，且无法关联持仓上下文。
